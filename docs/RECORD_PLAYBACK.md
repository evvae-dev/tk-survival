# 나의 기록 순차 재생

## 화면 동작

- 헤더의 `자동 ▶`는 자동 재생을 켜고 끈다. 기본값은 켜짐이다.
- `x0.5`, `x1`, `x1.5`, `x2`는 기록 사이의 **대기 시간 배율**이다. 기본 3초에 곱하므로 각각 1.5초, 3초, 4.5초, 6초다.
- `Ⅱ▶`는 자동 재생을 끄고 다음 기록을 한 건 진행한다. 마지막 기록까지 읽은 뒤 한 번 더 누르면 다음 선택 카드를 펼친다. 선택 카드가 보이는 동안은 비활성화된다.
- 직접 고른 행동의 결과는 즉시 기록한다. 이후 자동으로 이어지는 사건은 정해진 간격마다 한 건씩 추가한다.
- 새 기록은 기존 기록 위에 쌓이고 기록 영역을 맨 위로 스크롤한다. 기록 재생 중에는 중앙 선택 카드를 숨긴다.
- 다음 선택 지점에서는 마지막 기록을 읽을 시간을 기다린 후 선택 카드를 펼친다. 선택을 대신 누르지 않는다. 선택하면 기존 재생 설정에 따라 이어간다.
- 설정·능력치·정세 등 팝업을 열면 대기를 멈춘다. 팝업을 닫으면 설정한 간격부터 다시 센다.
- 재생 모드와 배율은 현재 화면에서만 유지한다. 새로고침하면 자동·x1로 돌아온다.

## 실행과 저장

화면에서 미래 기록을 숨기는 방식 대신 사건 엔진을 한 기록씩 실행한다. 아직 보여주지 않은 사건의 사망·점령·능력 변화가 정세 패널에 먼저 나타나지 않도록 한다.

1. `getCurrentEvent(game, catalog, true)`는 첫 자동 기록의 상태에서 멈춘다. 같은 사건 안에 다음 선택지가 있으면 해당 선택 노드의 커서를 보존한다.
2. `advanceRecord(expectedKey)`가 해당 상태를 Zustand에 저장한다. 이미 처리한 키를 다시 제출해도 추가 진행하지 않는다.
3. 자동 기록이 남아 있으면 `nextTurn`은 선택 요청을 받지 않는다.
4. `useRecordPlayback`이 타이머·배율·수동 진행·카드 공개 시점을 관리한다.

게임 저장 형식은 기존 persist 버전 6을 유지한다. 공개한 기록과 실행 커서·세계 상태를 함께 저장하므로 새로고침 뒤 이미 공개한 사건을 중복 실행하지 않는다. 기존 저장에서 이미 처리한 기록은 다시 재생하지 않는다.

## 확인 경로와 검증

현재 실행 중인 개발 서버는 `http://localhost:3000`이다. 시작할 때 Next.js가 출력하는 포트를 기준으로 접속한다.

관군 합류 → 완성으로 이동하면 대흥산 → 청주 → 완성 사전 기록이 한 건씩 추가되고 완성의 선택 카드가 펼쳐진다. 수동 진행·저장 복원·중복 진행 방지·진영과 전선별 연결·배율 계산은 `lib/record-playback.test.ts`에서 확인한다.

2026-10-16 검증: 타입 검사·프로덕션 빌드·테스트 106개를 통과했다. 실제 Chromium에서 데스크톱 1440×1000의 수동 진행·새로고침 복원, 모바일 390×844의 기본 3초·x0.5 간격·팝업 중 일시 정지·선택 지점 정지를 확인했다. 두 시나리오 모두 브라우저 실행 오류와 콘솔 오류는 없었다. 개발 서버의 실시간 연결·요청 취소는 화면 전환에 따라 발생했다.

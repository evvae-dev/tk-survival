# 챕터 서사·결과 작성 지침

화자는 삼국지의 미래를 아는 현대인이다. 미래 지식이 있어도 신분·인맥·전투 실력·현장 증거가 자동으로 생기지는 않는다. 문체는 짧고 캐주얼한 1인칭 웹소설 독백이며 억지 밈·설명투·긴 감각 묘사를 피한다.

- 제목은 `[도원결의에 출석 체크는 안 되나요?]`처럼 대괄호를 사용한다.
- 상황은 3~4문장으로 현재 위기·관찰·의도·판단의 계기를 연결한다.
- 선택은 `[구체적 행동] 속마음`이다. A는 원작 개입, B는 영웅과 접촉·합류, C는 생존 우선이다. 실제 상태에서 실행할 수 있는 행동을 제시한다.
- 결과는 행동→상대 반응→성패→실제 변화가 있는 과거형 1~2문장이다. 선택의 의도를 그대로 결과로 재사용하지 않는다.
- 판정 안내에는 짧은 성공·위험 힌트를 둔다. 실제 결과 본문은 선택 뒤에 기록한다. 조건 미달과 확률 실패를 구별한다.
- 진입·배경 기록에는 아직 결정되지 않은 기본 승리·사망·배신을 실제 발생한 일처럼 쓰지 않는다. 원본의 전체 요지는 별도 사실 데이터에 보존한다.
- 협상 성공과 신변 보장, 접촉 성공과 임관, 경계 강화와 암살 저지는 각각 다르다. 후속 선택에서 결정할 결과를 앞서 해결하지 않는다.
- 현재 세계에서 죽은 인물·패망 세력·바뀐 전제를 검사한다. 공통 후속 문장은 성공/실패 모두에 성립하게 쓰고 필요하면 장면을 나눈다.
- 정식 소속은 실제 이탈·변경까지 유지한다. 지역만 같다고 군주 지원을 열거나 외지 사건으로 순간 이동시키지 않는다. 이동은 관련 진입문과 실제 위치 효과로 연결한다.
- 배경/실제 결말/소식은 결과 노드의 명시적 `recordType`으로 기록한다. 사실 문장은 제목 없이도 주체·대상·장소·결과를 알 수 있게 쓴다. 기록은 발생 순서대로 표시한다.

## 시나리오 담당 지시 — 2026-10-23

[사건 참여 계약](EVENT_PARTICIPATION_CONTRACT.md)을 읽고 기획의 진입 결정표·상태 생산/소비표에 맞춰 작성하라.

- 현장에 왜 들어왔는지 실제 직전 결과로 설명하라. 접촉 실패자에게 초대·동행·군장 운반 경험을 문장으로 새로 부여하지 말라.
- 접촉, 출입 허락, 임시 동행, 정식 소속을 결과 문장에서 구분하라. 허락·거절을 작성했으면 개발 담당에게 저장할 상태와 후속 진입 조건을 함께 넘겨라.
- 불참자의 도원결의는 ‘유비·관우·장비가 복숭아밭에서 의형제를 맺었다는 소식을 들었다’처럼 소식으로 작성하라. 울타리 밖에서 직접 보거나 잔을 나른 것으로 쓰지 말라. 결의 자체가 불성립한 세계에는 이 소식도 쓰지 말라.
- 황건 경로는 주인공의 명시적인 합류 행동과 상대 반응을 작성하라. 이후 ‘아군’·‘적군’·명령권·전공의 주체를 해당 진영에 맞춰라. 같은 전투라도 이름만 바꾼 유비 측 장면을 복제하지 말라.
- 실패 후 닫힌 기회와 남은 활동을 드러내라. 같은 초대를 자동 재제공하지 말고 새 소개·증거 등 근거가 있을 때만 재도전으로 연결하라. 재야에도 일부 직접 행동을 배치하되 반복 업무로 채우지 말라.
- A/B/C는 기본 성격이다. 소식 전용 경로에 선택을 넣거나 개수를 맞추려고 불가능한 행동을 만들지 말라. 공통 장면에서는 앞선 성패·소속·생존을 보존하라.

인계물은 경로별 진입문·선택·실제 결과·불참 소식과 해당 상태/노드 대응이다. 원작 근거, 실제 플레이 결과, 게임 창작 대안역사를 구분한다. 문구만 바꾸고 참여 조건 구현까지 완료했다고 보고하지 않는다.

## 데이터·관리자 계약

원본 문서는 `docs/romance-three-kingdoms/chapters/`, 장면·분기 원본은 `data/chapters/chapter-NNN.json`, 생성기는 `scripts/build-story.mjs`, 공통 실행은 `data/history/events.json`이다. 재생성으로 문구·이미지·분기가 사라지지 않아야 한다.

추가한 사건·노드·선택·조건·판정·효과·연결·이미지는 게임과 `/admin/events`, `/admin/collection`에 함께 나타나야 한다. 관리자에서 편집→저장→새로고침→게임 반영을 확인한다. 새 판본의 편집 필드·배치·명시적 삭제는 보존하고 사용자 지시 없이 전체 그래프를 기본본으로 바꾸지 않는다. 문체만 고칠 때는 ID·조건·효과·연결·생존 판정을 바꾸지 않는다.

실행 흐름과 QA 기준은 `.agents/skills/three-kingdoms-flow/SKILL.md`, `.agents/skills/three-kingdoms-qa/SKILL.md`를 따른다. 해당 화의 확인된 오류가 모두 수정되고 장면별·챕터 종합 점수가 7점 초과여야 완료한다. 실제 수행한 검증과 미실행 범위를 구별해 보고한다.

## 최신 판정·표시 규칙

기록은 기본 5초, 결과 카드는 속도·문장 길이와 독립적으로 5초 표시한다. 모든 상황·선택·결과에는 환경이 포함된 이미지가 필수이며 중복 이미지도 숨기지 않는다. 단독 캐릭터 그림은 기준 참조로만 보존한다. 선택별 스탯 비중·상황 난도·성공 명성의 영향력 근거를 명시하고, 실패는 성공 명성의 정확히 절반을 차감한다. 음수·소수점·전사 실패도 예외가 없다. 현재 공식은 `docs/ABILITY_CHECKS.md`를 따른다.

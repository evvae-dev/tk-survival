# 연표·장수 수집 자료

> 2026-10-16 현재 활성 범위는 184년·20세 테스트와 5.1 실행 사건 7개, 상위 연표 6개입니다. 장수 1,000명은 유지합니다. 이전 연간 성장·전체 연표 설명은 당시 기록입니다. 현재 구현·저장·편집 방법은 [5.1 실행 문서](CHAPTER_5_1_RUNTIME.md)를 우선 확인하세요.

2026-10-16부터 사건 전개를 포함한 재수집을 절별로 진행한다. 첫 단위의 결과와 기존 자료의 차이는 [5.1 황건적의 난 재수집](COLLECTION_5_1.md)에 있다. 새 자료는 `data/collection/5-1-yellow-turban.json`이며 기존 연표·장수·Firebase 활성본을 덮어쓰지 않는다.

2026년 10월 15일 공개된 두 자료를 읽어 정규화했다. 중국어 원문·HTML 보관용 raw 폴더는 만들지 않았다.

## 수집 범위

- [나무위키 삼국지/연표](https://namu.wiki/w/삼국지/연표): 연도별 하위 목차 97개를 포함한 본문에서 사실 항목과 세부 경과 939개. 전체 범위는 127~316년이고, 현재 게임 범위인 170~280년은 866개다. 황건적의 난 이전과 통일 이후의 배경 자료도 보존한다.
- [삼국지14 전체무장 공유 시트](https://docs.google.com/spreadsheets/u/0/d/1Iq89ZA4E1-lqo4I9pGZdfqI3PUk-L75WEf3FaKmA0ww/htmlview): `전체무장 능력치/개성`과 `반에디터_원본` 두 탭 각 1,000행을 무장번호로 연결했다. 동일 인물을 2,000명으로 중복 등록하지 않는다. 두 탭의 이름·생몰년·등장년·능력치를 교차 검사했다.

자료 파일은 `data/reference/chronology.json`, `officers.json`, `metadata.json`이다. 사이트 URL과 목차·탭별 수집 정보는 메타데이터에만 둔다.

2026년 10월 16일 사용자 요청으로 출생 알림 87개와 단순 사망 알림 67개를 제외했다. 현재 활성 연표는 **785개**다. 손환의 두 출생 항목도 삭제 대상에 포함한다. 전투·정변·후계 승계 등 독립적인 역사 변화가 함께 있는 사건은 유지한다. 장수 데이터 1,000명과 생몰년 필드는 유지한다.

삭제 목록은 `data/reference/event-exclusions.json`에 연표와 게임 사건 ID별로 기록한다. 수집기는 이 ID를 다시 제외하고, 삭제한 부모 항목 아래의 남은 경과는 가장 가까운 유지 항목으로 연결한다. 현재 연표의 집계는 `timelineCount`, 원래 수집량은 `collectedTimelineCount`, 제외량은 `excludedTimelineCount`로 구분한다. 브라우저의 이전 편집본에도 같은 삭제 ID 필터를 적용한다.

## 인물 ID 연결

`relatedPeople`은 표시용 이름이고, `relatedOfficerIds`는 같은 자료 버전의 `officers/{id}`를 가리키는 장수 문서 ID 배열이다. Firestore의 자동 조인이 아니라 애플리케이션에서 조회할 수 있는 문자열 참조다. 예를 들어 조조는 `rtk14-0521`로 연결된다. 이름이 유일한 경우를 자동 연결한다. 동명이인은 사용자의 직접 지정이 우선이며, 이후 추가 요청한 생몰년 추정 연결은 별도 근거와 함께 표시한다.

2026년 10월 16일 사용자의 부분 답변을 적용했다. 순욱 Q015는 `rtk14-0397`, 왕기 Q031은 `rtk14-0046`이며 나머지도 지정된 사건별 ID를 사용한다. 유기 Q027의 `미상`은 `null` 결정으로 보존해 장수 ID를 지정하지 않는다. 출생·사망 삭제 후 남은 답변 결정은 20건이며 이 중 미상 1건을 제외한 19건은 ID 연결이다. 이 단계에서 답변하지 않았던 37건은 후속 요청에 따라 추정 연결했다.

질문 번호는 `data/reference/officer-link-questions.json`에 고정했다. 삭제된 사건은 문서에서 삭제 상태로 표시하며 번호를 재사용하지 않는다. 후속 요청으로 미답변 37건을 생몰년·문맥으로 추정 연결했다. `officer-link-inferences.json`과 `docs/OFFICER_LINK_INFERENCE.md`에 근거가 있으며 활성 연표의 동명이인 확인 대기는 0건이다. 명시적으로 미상으로 지정한 유기 Q027은 미연결로 유지한다.

사용자 확인이 필요한 인물은 `officerLinkIssues`의 `name`, `reason: "ambiguous"`, `candidateOfficerIds`에 남는다. 초기 자동 연결은 988건이고 동명이인 확인은 29개 이름·81건이다. 후보가 없는 경우는 `not-found`, 사용자가 미연결을 지정한 경우는 `excluded`다. 확인 질문과 후보 문서 ID는 `docs/OFFICER_LINK_REVIEW.md`에 있다.

답변은 `data/reference/officer-link-decisions.json`의 `decisions[연표 문서 ID][이름]`에 장수 문서 ID로 저장한다. `null`은 사용자가 지정한 미연결이다. 결정은 사건별로 적용하므로 같은 이름을 가진 다른 인물의 사건을 일괄 오인하지 않는다. 결정이 없는 동명이인은 게시 후에도 확인 대기로 유지한다.

```powershell
node scripts/link-reference-officers.mjs
node scripts/validate-reference-data.mjs
```

연결 도구는 인물 ID와 확인 목록을 갱신하며 질문 번호는 답변 적용 후에도 유지한다. 새로 크롤링할 때도 같은 결정 파일을 적용한다. 이전 결정에 해당하는 사건이 없어졌다면 임의로 버리지 않고 오류를 반환하므로 자료를 대조해야 한다. 게시 전에는 모든 연결 ID의 존재와 표시 이름을 검사한다.

`/api/timeline?officerId=rtk14-0521&includeOfficers=true`로 해당 장수의 사건과 `relatedOfficers` 데이터를 조회할 수 있다. 확인 대기 중인 후보 ID는 확정 연결로 검색되지 않는다. 관리자 수집 자료에 연결 ID와 확인 대기 후보가 표시되고 새 이벤트 초안에도 ID가 복사된다. 기존 브라우저 편집본은 자동으로 덮어쓰지 않으며, 편집기에서 인물 이름을 수정하면 이전 ID 연결을 지워 잘못된 참조를 남기지 않는다.

## 필드와 정확도

연표는 `id`, `year`, `month`, `precision`, `regionIds`, `factionIds`, `relatedPeople`, `content`, `source`, `parentId`를 가진다. `parentId`는 사건 아래의 설명을 연결한다. 월은 해당 항목 또는 상위 항목에 명시된 경우만 기록하며 형제 항목의 월을 전파하지 않는다. 지역·세력은 본문의 명시 어휘를 매칭한 보수적 태그이므로 완전한 지리·소속 판정은 아니다. 인물은 시트 이름과 본문 인물 링크가 일치할 때 연결하며, 식별하지 못한 사람은 누락될 수 있다.

원문서의 내용 자체에 원사서명이나 회차가 없는 경우 `source.title`은 `원사서 미확인`, `source.record`는 `null`이다. 역사 계열 분류가 원전 검증 완료라는 뜻은 아니다. 연의를 명시한 항목은 소설로 구분한다. 모든 사건에 사서기록을 새로 지어 넣지 않았으며 후속 원전 대조가 필요하다. 이 자료의 표현이나 연대 오류도 자동으로 정정했다고 주장하지 않는다. 예를 들어 원페이지의 190년 항목에는 장안 천도가 없어서 수집본에 임의 삽입하지 않았다. 게임의 기존 장안 천도 사건은 그대로 유지한다.

장수는 `rtk14-0001`처럼 게임 무장번호로 구분한다. 같은 이름의 노숙 두 명도 별도 ID다. `stats`는 통솔·무력·지력·정치·매력, `traits`는 개성이다. `gameData`에 정책·주의·소속·관계 등 반에디터의 이름이 확인되는 필드를 보존한다. 생몰년·등장년·사관년·관계는 삼국지14 설정값이며 역사적 사실로 검증한 값이 아니다. 시트의 비어 있는 세력은 현재 연도에 맞춰 추정하지 않는다. 의미를 모르는 `lp` 컬럼은 제외한다.

## 관리자와 게임 연결

`/admin/data`에서 자료 종류·검색어·연도를 지정한다. 연표의 **이벤트 초안 열기**는 170~280년 항목을 현재 브라우저의 사건 목록에 추가하고 해당 사건의 플로 편집기로 이동한다. 같은 수집 ID가 이미 있으면 기존 편집본을 덮어쓰지 않는다. 기본 지역 조건과 선택 플로를 제공하며, 문헌·지역·세력·분기는 편집기에서 보완할 수 있다. 초안을 공유하려면 기존 **저장된 목록 공유 게시**를 사용한다. 수집한 세부 경과를 기존 사건들과 별도의 게임 이벤트로 모두 자동 게시하지 않는다. 기존 게임 사건과 의미가 중복되는지는 관리자가 확인해야 한다.

`/api/timeline`은 `q`, `year`, `region`, `faction`, `person`, `category`, `page`, `limit`로 조회한다. `/api/officers`는 `q`, `id`, `location`, `year`, `page`, `limit`를 받는다. 장수의 `year`는 게임 생몰년 기준 생존 필터이며 당시 소속이나 출현 여부를 판정하지 않는다. 기본 50개, 최대 200개 단위다. API는 배포된 소스의 정규화된 스냅샷을 사용한다.

## Firebase와 다시 수집하기

공유 데이터는 `referenceCatalog/current`의 `revision`이 가리키는 `referenceCatalogRevisions/{revision}/chronology/{id}`와 `.../officers/{id}`에 저장된다. 현재 스냅샷은 연표 785개·장수 1,000명이다. 공개 게임 자료이므로 읽기는 공개하며 클라이언트 쓰기는 차단한다. 재수집·게시 도구만 Firebase CLI의 IAM 권한으로 새 스냅샷을 만든다. 모든 문서를 쓰고 수량을 확인한 뒤 포인터를 바꾸며, 포인터에는 변경 시각 선행 조건을 걸어 동시 게시를 감지한다.

기존 공유 게임 사건의 삭제는 `scripts/publish-event-exclusions.cjs --firebase-tools-dir <인증된-firebase-tools의-lib-경로>`로 적용한다. 이 도구는 서버의 현재 사건을 읽어 지정 ID만 제외하고 나머지 편집본을 그대로 새 버전에 보존한다. 소스 기본 목록 전체로 덮어쓰지 않는다. 과거 버전은 이력으로 남으며 현재 포인터가 가리키는 버전에서 삭제가 적용된다.

```powershell
node scripts/collect-reference-data.mjs
node scripts/validate-reference-data.mjs
node scripts/publish-reference-data.cjs --firebase-tools-dir <인증된-firebase-tools의-lib-경로>
```

같은 데이터의 체크섬이 이미 게시되어 있으면 다시 쓰지 않는다. 시트 탭·컬럼이 바뀌거나 시트 간 기본 값이 다르면 수집을 중단한다. Firebase 토큰·인증 파일을 Gemini나 수집 데이터에 전달하지 않는다.

## Gemini CLI 사용 내역

설치된 `sol-gemini-harness` 스킬을 확인했으며, 이번 요청에 따라 고정 모델 단계 대신 Gemini CLI를 사용했다. 설치된 CLI의 실행 환경에는 `web_fetch`와 터미널 실행 도구가 노출되지 않았고 검색은 서버 500 오류를 반환했다. 공개 페이지 다운로드·정규화는 로컬 수집 스크립트로 처리하고, 공개된 컬럼·수량·표본을 `gemini-3.8-flash`에 전달해 스키마를 검토했다. Gemini가 직접 두 사이트를 크롤링한 것으로 보고하지 않는다. 공개 데이터 외에 프로젝트 환경 파일·인증값은 전달하지 않았다.

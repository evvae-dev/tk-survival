# 능력 비교와 확률 판정

## 현재 규칙

주인공 능력은 통솔·무력·지력·정치·매력 다섯 개다. 체력·자금은 상태, 출신 가정 보정, 이동, 사건 조건·효과, 관리자 입력, 화면에서 제거했다. 이전 5.1 저장은 진행·세계·과거 기록을 유지하고 폐기된 두 수치만 제거한다. 구 저장 사건의 능력 조건도 새 판정으로 이관하며 원래 편집 문구는 보존한다.

상대 장수 B가 있는 경우:

```text
A 보정치 = A의 각 능력 × 해당 비중의 합
B 보정치 = B의 각 능력 × 같은 비중의 합
성공률 = 50 + (A 보정치 - B 보정치) × 전체 가중치
실패율 = 100 - 성공률
```

확률은 0~100%로 제한하고 소수 둘째 자리까지 계산한다. 동률은 50%다. 기본 전체 가중치는 1.5이며 `.env`의 `ABILITY_CHECK_WEIGHT`로 바꾼다. 설정 변경 후 개발 서버를 재시작하고, 운영 서버는 다시 빌드한다.

| 판정 | 보정치 |
|---|---|
| 전투 | 통솔 × 1.5 + 무력 × 1 |
| 일기토 | 무력 |
| 전략 | 지력 |
| 정치 | 정치 |
| 사람 관계 | 매력 |
| 복합 | 관리자가 지정한 여러 능력 × 비중의 합 |

상대 B가 없거나 해당 인물이 장수 데이터에 없으면 사용자 결정에 따라 **능력치 75 → 성공 75%**를 사용한다. 여러 능력이 섞인 상대 없는 판정은 보정치를 비중 합으로 나눈 가중 평균을 확률로 사용한다. 상대의 가상 능력치 50을 만들어 넣지 않는다.

예: 등무 `rtk14-0746`의 무력은 장수 자료에서 76이다. 주인공 무력 96이면 `50 + (96 - 76) × 1.5 = 80%`, 무력 56이면 20%다. 게임 수치는 역사적 실력의 측정값이 아니다.

## 데이터와 관리자

- `flow.nodes[].type = check`로 능력 판정을 표현한다. 조건 노드는 지역·소속·생존·세계 표식 같은 확정 조건을 담당한다.
- `data.check.kind`: `battle`, `duel`, `strategy`, `politics`, `relationship`, `custom`.
- `data.check.opponentId`: 상대 장수 문서 ID. 없는 인물을 임의의 장수에게 연결하지 않는다.
- `data.check.weights`: 복합 판정에서 사용할 능력별 비중. 음수·무한대·모든 비중 0은 허용하지 않는다.
- `data.check.success/failure`: 선택 전에 보이는 성공·실패 요약. 실제 YES/NO 간선과 결과·후속 단계를 일치시킨다.
- 상대 능력은 `data/reference/officers.json`에서 생성한 경량 자료 `officer-abilities.json`으로 읽는다. 생성기를 실행하면 원본의 ID·이름·능력을 다시 반영한다.
- 상대 B가 있으면 이름과 관련 능력 아이콘을 표시한다. 성공 설명·확률은 파란색, 실패 설명·확률은 빨간색이다. 판정 없는 선택은 확정 결과를 표시한다.
- 관리자 노드 편집기에서 판정 종류·상대 ID·복합 비중·성공/실패 요약을 변경한다. 능력 판정은 선택 노드 바로 뒤에 연결하고 YES/NO를 결과 또는 다음 선택으로 연결한다.

## 실행과 저장

화면 미리보기와 `getCurrentEvent`는 추첨하지 않는다. 선택을 제출할 때 `resolveChoice`가 한 번 추첨하고 YES/NO 경로를 실행한다. 그 뒤 진행 커서·사건 상태·효과·판정 종류와 비중·상대 ID·보정치·확률·추첨값·성공 여부를 결과 기록에 저장한다. 새로고침이나 지난 선택 키의 재제출로 결과를 다시 추첨하지 않는다. 게임 저장 버전은 6이다.

5.1 문구는 최신 [이벤트 작성 지침](EVENT_WRITING_GUIDE.md)의 1인칭·짧은 독백·대괄호 제목·행동과 속마음 형식을 적용했다. 사료 원본과 인물·장소의 사실 관계는 이번 변경으로 수정하지 않는다.

실행 사건은 7개, 선택 장면은 20개, 선택지는 56개, 확률 판정 노드는 31개다. 현재 Firebase 공유 리비전은 `0e7e8932-851b-4a90-8caf-de6673ffeb54`이며 이전 `eccb1f96-fae9-4a6d-ad66-31985f3a7a92`도 보존했다. 공유 게시 전 예상 리비전과 저장 후 전체 내용을 비교해 다른 게시를 조용히 덮어쓰지 않도록 했다.

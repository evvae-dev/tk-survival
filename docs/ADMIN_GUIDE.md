# 사건 관리 사용법

## 관리자 담당 지시 — 2026-10-23

현재 챕터의 분기 개선은 [사건 참여 계약](EVENT_PARTICIPATION_CONTRACT.md)을 따른다. 아래 5.1~5.5 사건 수·노드 예시는 과거 판본 사용 기록이며 현재 `rNNN-NN`의 완료 상태가 아니다. 현재 판본은 `romance-participation-v2`이며 아래 요구를 공통 그래프에 구현했다. 검증 근거와 다음 개발 인계는 [재개발 기록](development/rebuild-participation-1-5.md)을 따른다.

1. 게임과 같은 공통 `flow`에서 성립 조건→참여 조건→진영/역할→현장 연결을 보여라. 불참 소식·조용한 종료·취소/대체 연결도 조회·편집할 수 있어야 한다.
2. 조건·효과에 알아볼 수 있는 라벨을 붙이고 접촉 표식과 동행/참석 권한을 구분하라. 단순 다음 사건 연결선을 성공 조건처럼 설명하지 말라.
3. 선택 노출 조건만으로 사건 전체의 참여 제한을 대신하지 말라. 현장 이동·배경보다 앞에 참여 검사가 있는지 확인하라. 공통 종료 효과가 진영별 결말을 덮어쓰지 않는지도 검사하라.
4. 원본에 새 선언 항목을 도입하면 생성된 노드와 실제 편집 위치를 연결해 문서화하라. 편집할 수 없는 게임 전용 분기를 만들지 말라.
5. 격리된 저장에서 진입 조건과 불참 소식/효과를 편집→흐름 저장→새로고침→게임 반영하라. 참/거짓 두 상태와 다른 진영을 확인하고 기존 문구·배치·연결·명시 삭제·확정 플레이 결과를 보존하라.

인계물은 변경 사건/노드 ID, 관리자 위치, 편집 전후 기대 경로와 실제 검증 증거다. 로컬 편집 검증과 외부 공유 게시를 구분한다.

현재는 게임과 동일한 다크 배경·빨간 강조색을 사용합니다. 전체 화면 구조와 파일 분리는 [UI 적용 문서](UI_REDESIGN.md)를 참고하세요.

`/admin/events`에서 사건을 검색하고 정보를 편집합니다. 제목·인물, 연도 범위, 정사·연의 분류로 목록을 좁힐 수 있습니다. 신규 사건은 자동으로 고유 ID를 받으며, 복제하면 별도 사건으로 저장할 수 있습니다.

## 수집 플로우 보기

`/admin/collection`의 기본 **게임 실행 플로우** 탭은 실제 게임과 같은 1~5화 사건41건을 표시한다. 사건 간 연결에서 노드를 두 번 누르거나 목록에서 선택하면 내부 조건·선택·결과를 본다. 노드 바로가기로 확대하고, 편집 링크로 해당 사건의 실제 편집기를 연다. 선행 사건 ID·실행 순서·사건 간 연결도 사건 속성에서 편집한다. 조건 노드와 결과 효과가 실제 인과 판정을 결정한다.

과거 수집 원자료와 실행 목록은 구분한다. 현재 원작은 `docs/romance-three-kingdoms/chapters/001.md`~`005.md`이며 원본 선언 필드는 [사건 데이터](EVENT_DATA.md)를 확인한다.

참여 조건은 `world-requires-*`(세계 성립), `<route>-eligible-*`(참여/진영), `<route>-arrival`(허가 후 이동), `<route>-background`(배경) 순으로 생성된다. `news-*`는 소식, `world-*`는 무관 사건의 조용한 세계 처리, `cancel`은 원래 사건 취소다. `<route>-<choice>-ok/fail`에는 실제 개인 결과와 그림, `outcome-*`에는 조건별 세계 결말이 있다. 노드 속성에서 조건·문구·효과·결과/소식 이미지를 편집하고 ‘흐름 저장 · 게임 반영’을 누른다.

새 판본은 `tk-survival-event-catalog-participation-v2`를 사용한다. 옛 판본 JSON 가져오기는 거부하며, 같은 번호의 옛 그래프를 자동 복원하지 않는다. 새 판본 안의 편집·명시 삭제는 유지한다.

## 편집본 저장 범위

편집 내용은 현재 브라우저의 로컬 저장소에 보관됩니다. 같은 브라우저에서 게임을 진행할 때 반영됩니다. Firebase를 설정하지 않으면 다른 기기나 브라우저에는 자동으로 전달되지 않습니다. Firebase 공유 설정을 마치면 관리자 로그인 후 공유 카탈로그를 불러오거나 게시할 수 있습니다. 로컬 편집의 저장과 공유 게시를 구분해 사용합니다. JSON 내보내기로 전체 유효 사건 목록을 백업하고, 가져오기로 목록 전체를 교체할 수 있습니다. 잘못된 사건이나 흐름이 포함되면 가져오기를 거부합니다. 전체 기본값 복원은 편집·삭제 내역을 모두 지웁니다.

## 사건 정보와 흐름

연도, 음력 월, 대략적인 시기 여부, 지역, 세력, 관련 인물, 내용, 문헌명과 한글 사서 기록을 입력합니다. 월을 모르면 비워 둡니다. 관련 인물은 쉼표로 구분합니다.

‘사건 정보 저장’은 정보만 저장하고 원래 게임 흐름을 보존합니다. 기존 사건에 저장된 흐름이 없으면 캔버스는 편집용 기본 초안을 보여 줍니다. 이 초안이 기존 게임 동작을 그대로 재현한다는 뜻은 아닙니다. ‘흐름 저장 · 게임 반영’을 눌러야 편집한 그래프가 게임 실행 흐름이 됩니다. 되돌리기는 마지막으로 불러오거나 저장한 상태를 복원합니다. 다른 사건으로 이동할 때 미저장 변경은 확인 후 버립니다.

흐름을 저장하면 기존 코드의 참가 조건과 세계 효과도 교체합니다. 특정 세력의 생존이나 이전 사건의 결과가 필요하면 조건 노드와 효과 적용 조건으로 직접 넣어야 합니다. 빈 세계 효과 목록은 기존 세계 효과를 적용하지 않겠다는 뜻입니다. 일부 사건에는 참가·관찰의 공통 흐름이 제공되며, 모든 사건에 개별 역사 개변 결과가 완성된 것은 아닙니다.

공유 저장의 프로젝트 설정과 관리자 UID 등록 절차는 [Firebase 연결](FIREBASE_SETUP.md)을 참고합니다.

## 노드와 연결

시작, 조건, 선택, 결과, 종료 노드를 추가할 수 있습니다. 노드를 끌어 배치하고 아래 연결점에서 다른 노드 위쪽 연결점까지 끌어 연결합니다. 선을 클릭한 뒤 Delete 키로 삭제합니다. 노드 삭제 시 연결도 함께 삭제됩니다. 전체 보기로 모든 노드를 보고 정렬로 배치를 정돈합니다.

시작·결과의 ‘다음’ 연결은 하나씩 필요합니다. 조건의 YES는 참, NO는 거짓 경로이며 둘 다 연결해야 합니다. 선택 노드의 각 선택지는 고유 연결점을 갖습니다. 선택지를 지우면 해당 연결도 삭제됩니다. 시작과 종료는 각각 하나이며, 도달 불가능한 노드나 순환 경로는 저장할 수 없습니다. 점검 목록에서 오류를 확인합니다.

## 조건과 결과

조건은 나이·연도·능력·현재 지역·소속 세력·출신·역할·세계 표식·세계 세력 상태·인물 생존·지역 지배를 비교합니다. 같음, 다름, 이상, 이하, 초과, 미만, 목록 포함을 지원합니다. 능력과 나이는 숫자, 세계 표식은 참·거짓을 사용합니다. 목록 포함은 쉼표로 구분한 내부 ID 목록입니다. 세계 표식 필드명은 `world.flags.이름`, 세력 상태 필드명은 `world.factions.세력ID` 형태로 입력합니다.

결과 노드에는 표시할 대사와 효과를 입력합니다. 능력·평판 증감, 지역 이동, 소속·역할 변경, 세계 표식, 세력 상태, 지역 지배, 인물 생존 효과를 지원합니다. 사망한 인물은 생존 효과로 부활하지 않습니다. 증감량은 음수로 감소시킬 수 있습니다. 효과마다 적용 조건을 추가할 수 있으며 여러 조건은 모두 참이어야 합니다. 사건 종료 시 공통 세계 효과도 같은 방식으로 편집합니다. 기존 적용 조건은 수정하지 않는 한 보존됩니다.

## 관리자 화면 구성

[Flowbite Admin Dashboard](https://github.com/themesberg/flowbite-admin-dashboard)의 탐색 구조와 밝은 카드형 배치를 참고했습니다. 기존 React 화면에 흰색 상단바·사이드바, 파란 강조색, 사건 목록·흐름·속성 카드를 적용했으며 외부 대시보드 실행 코드나 샘플 데이터를 가져오지 않았습니다. 상세 기준은 [관리자 화면 설계](ADMIN_UI.md)를 참고하세요.

상단의 전체 사건·정사·연의·실행 흐름 등록 수는 현재 유효 카탈로그에서 계산합니다. 왼쪽 메뉴에서 사건 기록, 게임, 공유 저장소로 이동합니다. 모바일에서는 메뉴 버튼으로 탐색을 열고 배경 클릭이나 Escape 키로 닫습니다. 속성 카드의 사건 정보·노드 속성 탭으로 편집 대상을 전환하며 그래프 노드를 클릭하면 노드 속성이 열립니다.


## 상황·선택 이미지 편집

사건 관리에서 선택 노드를 누르고 **노드 속성 → 상황 이미지 / 선택 N 이미지**를 연다. 기본 이미지 사용·직접 지정·이미지 없음 중 선택하고, 직접 지정할 때는 공개 아트 경로(`/art/choices/…png`, `/art/scenes/…png`)와 대체 설명을 입력한다. 미리보기로 장면을 확인한 뒤 **흐름 저장 · 게임 반영**을 누른다. 새로고침과 JSON 내보내기·가져오기에서도 설정이 유지된다. 다른 브라우저에도 적용하려면 기존 공유 게시 기능을 사용한다.

과거 황건 천하통일 사건(`chapter-5-1-yellow-conquest`)의 노드 예시는 이전 판본 기록이다. 현재 이미지 기준은 모든 상황·선택·결과에 환경이 있는 장면을 표시하고 중복 이미지도 숨기지 않는 것이다. 참여·진영별 연결은 [이미지 생성 규칙](IMAGE_GENERATION_RULES.md)을 따른다.


## 5.1~5.5 사건과 합류 조건 (2026-10-19)

전체 목록은 28개 사건이며 [현재 실행 문서](CHAPTER_5_1_TO_5_5.md)에 ID와 직접 링크를 정리했다. 사건 정보에서 챕터 5.1~5.5를 지정할 수 있고 제목·사건 ID·내부 노드 ID로 검색한다.

선택 노드의 각 선택지 안에서 **선택 노출 조건**을 펼치면 지역·나이·군주 생존·세력 상태 등의 조건을 추가·수정·삭제할 수 있다. 여러 조건은 모두 충족해야 하며 한 항목의 여러 후보는 `목록에 포함`으로 지정한다. 조건을 만족하지 않는 지원 선택은 게임에서 표시하지 않는다. `offers`의 재야 이동 선택은 기본 대체 경로이므로 모두 막히는 조건을 임의로 추가하지 않는다.

합류 확률은 연결된 `check-*` 노드에서 사람 관계(매력) 판정으로 편집한다. `accepted-*`의 소속·역할·활동 지역 효과와 `rejected-*`의 거절 결과·재야 이동 연결을 함께 확인한 뒤 ‘흐름 저장 · 게임 반영’을 누른다. 새 분기를 화면에만 별도로 추가하지 않는다.

`/admin/collection`의 ‘5.2~5.5 수집 원자료’에서 각 사건의 배경·전개·결과, 참가 역할·장수 ID, 시기 이견, 실제 조회 URL·절·접근 유형·라이선스를 확인할 수 있다. 게임 창작 문구는 사건 관리에서, 사실 자료는 수집 JSON에서 구분해 관리한다.

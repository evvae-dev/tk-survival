# 사건 참여·분기·결과 전파 계약 — 2026-10-23

이 문서는 r001-01~r001-05 검토에 따른 후속 개발 기준이다. 이번 반영은 스킬·문서 정비이며 게임 데이터·생성기·엔진의 구현 완료를 뜻하지 않는다. 이후 구현 요청의 범위 안에서 적용한다. 120회 전체를 지금 개발하거나 배포하라는 지시가 아니다.

후속 사용자 요청으로 기존41건을 폐기하고 1~5화를 실제 재개발했다. 당시 문서 정비 범위와 구분한 현재 구현·검증 기록은 [재개발 기록](development/rebuild-participation-1-5.md)에 둔다. 아래 인수 기준은 새 판본에도 계속 적용한다.

기존 조건·판정·효과·기록·저장 엔진을 유지하고 사건 진입 규칙과 생성기를 보완한다. 전용 스케줄러, 새 게임 엔진, 관계 수치 시스템을 선행 과제로 만들지 않는다. 기존 구조로 표현할 수 없는 요구가 확인된 경우에만 근거와 영향 범위를 남기고 필요한 부분을 확장한다.

참여·불참·진영·결과 연결에서는 이 계약이 과거의 일괄 현장 진입, 선택지 세 개 강제, 고정 역사 결말 규칙보다 우선한다. 기록 5초·결과 5,000ms, 판정·명성, 이미지, 사용자 편집·확정 결과 보존 규칙은 계속 적용한다.

## 1. 팀 공통 목표와 책임

**선택 때문에 다음에 갈 수 있는 현장과 할 수 있는 행동이 달라져야 한다.** 문구·보상만 다른 것을 사건 참여 분기의 완료로 인정하지 않는다. 모든 사소한 선택에 별도 사건을 만들 필요는 없지만, 동행 허락·거절·합류·이탈·역사 변경처럼 후속 참여의 전제를 바꾸는 결과는 실제 조건으로 소비해야 한다.

담당은 업무 책임의 구분이다. 한 작업자가 여러 역할을 수행할 수 있으며 별도 에이전트 생성이나 단계별 사용자 재승인을 요구하지 않는다.

| 담당 | 지시 | 인계 산출물 | 반려 기준 |
|---|---|---|---|
| 기획·분기 | 사건 성립과 주인공 참여를 분리하고 핵심 갈림길만 설계하라 | 진입 결정표, 상태 생산·소비표, 경로별 종료 상태 | 실패해도 성공자의 현장·권한을 그대로 얻음 |
| 시나리오 | 진입 근거와 성패가 다음 행동을 낳는 이유를 써라 | 현장·진영별 장면, 불참 소식, 실제 결과 문장 | 초대·동행·전공을 문장으로만 만들어 줌 |
| 데이터·개발 | 조건을 현장 효과보다 먼저 실행하고 공통 그래프로 생성하라 | 원본 데이터, 생성기, 실행 목록, 호환 처리 | 숨은 분기, 재생성 시 유실, 불참자의 강제 이동 |
| 관리자 | 진입·불참·진영·결말 조건을 조회·편집 가능하게 하라 | 공통 플로우, 편집·저장·복원·게임 반영 증거 | 게임만 분기되고 관리자에는 연결이 없음 |
| QA | 직전 선택부터 후속 사건까지 성패 경로를 대조하라 | 엔진 재현, 기대/실제 상태, 화면 증거 | 단일 사건 통과·노드 수·점수만으로 인과 검증 대체 |
| 아트·화면 | 참여 여부와 진영에 맞는 시점·이미지를 적용하라 | 경로별 이미지 연결표와 PC/모바일 검수 | 불참자를 현장에 그림, 황건 측을 유비 아군으로 표현 |
| 통합 | 인계표와 실행 증거를 맞춰 완료를 판정하라 | 미해결 항목, 완료 상태, 다음 사건 진입 계약 | 설계를 구현 완료로 보고하거나 상태를 초기화해 합류 |

## 2. 사건 시작의 판정 순서

1. **처리 순서:** 필요한 선행 사건이 처리됐는지 확인한다. 처리 완료는 성공·참여·동행을 뜻하지 않는다.
2. **세계에서의 성립:** 필수 인물·세력·전투 전제 등 현재 상태에서 사건이 발생할 수 있는지 확인한다. 성립하지 않으면 원래 장면·기본 결말을 실행하지 않고 취소 또는 정의된 대체 경로로 간다.
3. **주인공 참여:** 실제 초대·동행·소속·접근 근거·위치 또는 허가된 이동 경로를 확인한다. 단순 지역 일치, 인물 등장, 앞 사건 완료만으로 참여를 허용하지 않는다. 공개 장터처럼 누구나 접근 가능한 사건도 그 근거를 명시한다.
4. **진영·역할:** 참여가 성립한 상태에서 어느 편의 어떤 역할인지 고른다. 서로 충돌하는 조건의 우선순위와 기본 경로를 명시한다.
5. **현장 실행:** 해당 경로에만 이동 효과·진입문·배경·선택을 적용한다. 비참가자에게 먼저 현장 도착을 적용한 뒤 소식으로 되돌리는 구현을 금한다.

| 판정 | 실행 | 기록·세계 처리 |
|---|---|---|
| 사건 성립 + 참여 가능 | 해당 진영의 현장 장면 | 실제 선택과 그 결과를 기록 |
| 사건 성립 + 불참 + 관련 소식 필요 | 선택 없이 소식 경로 | 현재 세계와 양립하는 NPC 결과를 한 번 적용하고 `news` 카드 기록 |
| 사건 성립 + 불참 + 무관 | 개인 장면 없이 처리 | 필요한 세계 효과와 처리 표식만 적용; 빈 카드 생성 금지 |
| 사건 불성립 | 원래 사건 취소 또는 정의된 대체 경로 | 원래 사망·승리·동행 효과 금지; 여정에 필요한 변경 소식만 기록 |

불참·취소도 후속 순서가 막히지 않게 처리 완료를 남긴다. 처리 표식과 실제 참여·성공 상태는 별개다. 불참에는 선택 판정·개인 명성·성장·전공·소속·임의 이동을 부여하지 않는다. 명시적인 세계 시간 진행과 NPC 결과는 개인 보상과 구분한다. 자동 기록과 다음 사건 전환은 기존 재생 정책을 따른다.

## 3. 상태 생산·소비 계약

- 접촉, 출입/초대 허락, 임시 동행, 정식 소속, 거절/경계를 구분한다. 새 enum이나 관계 수치부터 만들지 말고 기존 필드·표식으로 표현 가능한지 확인한다.
- 중요한 상태마다 `생성 사건/선택/결과 → 저장 위치 → 읽는 후속 사건/조건 → 해제·유효 범위`를 작성한다. 로그 문구 검색이나 사건 완료 여부로 성공을 추정하지 않는다.
- `metLiuBei`는 접촉 증거일 뿐 도원결의 참석 허가가 아니다. `liuSponsor` 같은 기존 표식도 실제 의미와 유효 범위를 정하고 초대·동행을 무제한으로 추론하지 않는다.
- 접촉 성공 뒤 동행 거절을 받은 경로에서는 접촉 사실을 지울 필요는 없지만 동행 권한은 없어야 한다. 이전 허락과 이후 거절이 겹칠 때의 해제·우선순위를 작성한다. 관계 없는 실패가 기존 소속을 자동 박탈해서도 안 된다.
- 중요한 성공·실패가 후속 조건 어디에서도 읽히지 않으면 누락으로 검토한다. 즉시 끝나는 국소 결과라면 이유를 명시한다. 모든 표식에 억지 후속 분기를 만들지는 않는다.
- 소속 변경·이탈은 실제 선택과 결과로만 확정한다. 유비 접촉 실패자를 자동으로 황건군에 가입시키거나 황건 소속을 다음 사건에서 유비 소속으로 되돌리지 않는다.

## 4. 120회 분량을 감당하는 분기 원칙

- 공통 시대 흐름 위에 핵심 갈림길과 필요한 진영별 장면만 둔다. 모든 사건·챕터마다 세 루트나 대안역사를 의무적으로 추가하지 않는다.
- r001-01~05의 시범 범위는 유비 접근·황건 접근·재야 경로로 설계한다. 구체 선택 문구·판정 수치는 후속 구현 때 확정한다. 황건 합류는 명시적인 의도와 접근 조건, 합류 결과가 있어야 한다.
- A 원작 개입/B 관계·합류/C 생존은 행동을 다양하게 만드는 기본 틀이다. 진영 수와 선택지 수를 혼동하지 않는다. 실제 가능한 행동만 노출하며 소식 전용 경로에는 선택지를 만들지 않는다. 현장 선택이 모두 막히면 유효한 대체 경로로 연결한다.
- 실패는 그 기회를 닫거나 조건을 바꾸되 이후 다른 활동으로 이어지게 한다. 같은 만남을 이름만 바꿔 즉시 재시도시키지 않는다. 재도전에는 새 증거·소개·시간 경과 등 새 근거가 있어야 한다.
- 재야는 피난·거래·정보 전달 같은 자기 처지의 활동을 일부 갖는다. 실패나 관망을 골랐다는 이유로 이후 모든 챕터를 소식만 읽게 하지 않는다. 분량을 채우기 위한 반복 업무는 금한다.
- 공통 사건으로 다시 합류할 수 있으나 소속·생존·거절·실제 전공을 초기화하지 않는다. 도착 시점이 같아도 진영·역할별 허용 행동은 다를 수 있다.
- 대안역사는 우선 국소적인 변화 하나가 후속까지 유지되게 설계한다. 예: 황건 측 출전 만류 성공 → 등무 생존·일부 철수. 이는 게임 창작 예시이며 원작 사실이나 구현 완료 기능이 아니다.

## 5. r001-01~05 인수 기준

다음은 후속 개발의 기대 동작이다. 모든 경로가 현재 구현됐다는 뜻이 아니다.

| 대상 | 담당자에게 요구하는 동작 |
|---|---|
| r001-01 | 고발·모집 탐색·은신 결과 중 후속 경로에 쓰는 정보와 국소 결과를 구분하라. 황건 접근의 발판을 두면 선택 근거를 함께 작성하라. |
| r001-02 | 유비 접촉의 성패와 초대 여부를 구분하라. 실패 후 r001-03에서 같은 접촉 기회를 자동 제공하지 말고 별도 접근 근거가 있는 경우만 허용하라. |
| r001-03 | 접근 근거로 주막 장면을 열고 동행·출입 허락과 거절을 r001-04 진입 조건에 연결하라. 단순 접촉만으로 참석 권한을 만들지 말라. |
| r001-04 | 허락이 있으면 현장 진행. 허락이 없거나 거절됐다면 세계에서 결의가 성립하는 경우 소식 카드만 기록하고 선택 없이 통과시켜라. 결의가 불성립하면 결의 완료 기록도 남기지 말라. |
| r001-05 | 유비 측 동행/소속, 황건 측 합류, 불참을 구분하라. 유효한 동행/소속 근거 없이 주인공을 자동으로 유비 측 전장에 세우지 말라. 대체 생존 결과를 고정 적장 사망으로 덮어쓰지 말라. |

필수 연속 경로는 `접근 성공→동행 허락→현장`, `접촉 성공→동행 거절→결의 소식`, `미접촉/관망→결의 소식`, `명시적 황건 합류→황건 측 장면`, `사건 전제 소멸→원래 결과 없음`이다. 범위 밖 후속 사건은 구현하지 않아도 인계할 종료 상태를 명시한다.

## 6. 구현·호환 지시

- 원작 근거는 `docs/romance-three-kingdoms/chapters/NNN.md`, 게임 장면 원본은 `data/chapters/chapter-NNN.json`, 생성기는 `scripts/build-story.mjs`, 공통 실행은 `data/history/events.json`이다. 원작 문서에 플레이어 분기를 섞지 않는다.
- 기존 `start/condition/result/choice/check/end`로 진입 판단과 소식·취소 경로를 먼저 구현한다. 설계표 항목을 지원 확인 없이 새 JSON 필드로 넣지 않는다. 원본 스키마를 확장하면 생성·검증·관리자 편집·저장 호환을 함께 처리한다.
- `prerequisiteEventIds`는 필요한 처리 순서에만 사용한다. `connections`의 다음 사건 표시만으로 성공 조건을 대신하지 않는다. 조건과 결과는 관리자에서도 보이는 공통 `flow`에 둔다.
- 공통 종료 효과(`passiveEffects` 포함)가 모든 경로에 적용되는지 점검한다. 진영별 승리·사망·소속 효과는 해당 조건/결과에서만 확정한다. 모든 경로에 적용 가능한 세계 효과만 공통으로 둔다.
- 저장된 선택·판정·기록·명시적 삭제·관리자 편집·진행 커서를 보존한다. 새 권한이 없는 옛 저장을 사건 완료나 지역 일치만으로 성공 이관하지 않는다. 실제 증거로 복원하거나 문서화된 호환 경로를 두며 이미 열린 선택을 소급 취소하거나 과거 효과를 재실행하지 않는다.
- 재생성 전후 의미 비교와 관련 실행 검증을 수행한다. 텍스트 변경만 하는 작업에서는 분기 구조를 몰래 바꾸지 않는다.

## 7. QA와 완료 지시

- 단일 사건을 초기 상태로 띄우는 테스트와 별개로 직전 사건의 실제 결과부터 다음 사건까지 실행하라. 실패 경로에서 현장·선택·이동·보상이 **없음**도 검증하라.
- 시작 상태, 선택 ID, 제어한 판정, 기대 참여 방식, 실제 노드, 기록 유형, 위치·소속·생존 변화, 다음 사건을 증거로 남겨라. 표식 주입은 조건 경계 검사에 쓸 수 있으나 연속 플레이 증거를 대신하지 않는다.
- 불참 후 세계 효과 누락, 취소 후 기본 결말 부활, 재진입·재제출·저장 복원 후 효과와 카드 중복을 검사하라.
- 같은 능력치에서 앞선 결과만 달리한 경로를 대조하라. 성패 모두 같은 장면·권한이면 설계상 국소 결과인지 중요한 분기 누락인지 판정하라.
- 기존의 ‘항상 선택 3개’, ‘모든 사건에 플레이어 참여’, ‘실패해도 도원결의 현장 접근’을 정상으로 보는 테스트는 새 기대 동작으로 교체하라. 단순 삭제·skip·단언 완화로 통과시키지 말라.
- 관리자 편집→저장→새로고침→게임 반영과 PC/모바일의 소식 카드→다음 유효 사건 전환을 검증하라. 숨긴 선택을 위조 요청해도 실행되지 않아야 한다.
- 기존의 오류 0개·장면/챕터 종합 7점 초과에 더해 대상 범위의 참여·불참·다른 진영·저장 호환 검증이 완료돼야 한다. 분기 수나 평균 점수로 결함을 상쇄하지 말라.
- 문서만 수정한 작업은 링크·규칙 일관성·변경 범위를 검증하고 게임 구현·실행 QA는 미수행으로 보고하라.

# 기록·군주 동행·5.1~5.5 사건 개편 설계

## 현재 기록 담당 지시 — 2026-10-23

[사건 참여 계약](EVENT_PARTICIPATION_CONTRACT.md)의 현장/불참/취소 판정을 따른다. 아래 5.1~5.5의 작업 순서·스키마 확장·검증은 과거 판본 기록이며 이번 문서 작업에서 다시 수행할 절차나 현재 구현 완료 증거가 아니다.

- 접촉 사실, 초대/출입 허락, 임시 동행, 정식 소속을 분리하라. 앞선 접촉 성공이 이후 동행 거절을 무효화하지 않게 하라.
- 불참 기록은 실제로 성립한 세계 경과의 `news`로 남겨라. 주인공의 현장 경험·개인 전공·성장으로 기록하지 말라. 도원결의 불참에는 현장 선택을 붙이지 말라.
- 세계 전제가 사라졌으면 원래 결의·승리·사망을 소식으로도 확정하지 말라. 정의된 대체 결과나 현재 여정에 필요한 변경 소식만 남겨라.
- 필요한 NPC 효과는 불참에도 한 번 적용하되 개인 이동·소속·보상과 분리하라. 소식이 필요 없는 사건은 빈 카드 없이 처리하라.
- 기록 ID·순서·공개 커서·기존 5초 재생 정책을 보존하라. 불참 처리 경계의 저장 복원에서 카드/효과 중복과 다음 사건 정지가 없는지 검증하라.

기록 유형은 사료 여부와 별개다. 대안역사 결과를 원작 사실로 표시하지 않으며, 관리자에서 실제 기록 노드·조건·효과를 편집할 수 있어야 한다.

2026-10-20 사용자 요청에 따른 재사용 요구사항 및 구현 계약. 승인 범위는 5.1~5.5이며 5.6 이후 수집은 포함하지 않는다. 작업 순서는 GPT-6.1 Sol 높은 추론의 분석·설계 → 낮은 추론의 구현 → 높은 추론의 전체 검증이다. 설계 계약과 이후 구현·검증 근거를 함께 보존하며, 실행 결과는 아래 검증 기록을 따른다.

## 반드시 유지할 사용자 요구사항

- 5.1 뒤에는 **5.1에서 실제 동행한 군주 한 명에게만** 지원할 수 있다. 조조 동행이면 조조만, 유비 동행이면 유비만 나온다. 같은 기주에 있다는 이유로 둘 다 나오면 안 된다. 임시 동행은 정식 소속과 다르며 지원 성공 뒤 말단 병사가 된다.
- 매력 판정으로 거절되면 재야 상태로 **다음 사건이 있는 지역들 중 목적지를 직접 선택**한다. 실패 뒤 임의 이동·재추첨·다른 군주에게 즉시 다시 지원하는 경로를 만들지 않는다.
- 개인 행동과 역사 흐름을 한 **기록** 패널로 합친다. PC 오른쪽을 넓히고 모바일도 기록은 하나만 표시한다. 두 패널을 번갈아 올리는 동작은 제거한다.
- 사건의 역사적 배경은 관련 장면 진입 시 알려 준다. 사료의 결말은 실제 전개와 양립할 때만 결말에 기록한다. 황건 승리·전투 취소·포로 생존에 관군의 사료상 승리·전사를 덮어쓰지 않는다.
- `원사서 미대조 · 2차 자료 요약:` 및 조사 과정·데이터 연결·실행 엔진을 설명하는 문장을 플레이어 사건 정보·본문·기록에서 제거한다. 실제 출처명·정사/연의/가상 구분은 정직하게 유지하고 조사 상태·이견은 관리자 원자료에 보존한다.
- 이동 버튼만 반복하지 않고 사건마다 다른 행동·상대 반응·성패·다음 선택이 이어져야 한다. 5.1~5.5 전체를 사건 맥락과 서사의 인과까지 검수한다.
- 새 분기는 공통 사건 목록의 `flow`로 등록하여 `/admin/events`에서 조건·판정·효과·연결을 편집하고 `/admin/collection` 실행 플로우에서 조회한다. 기존 사용자 편집·명시적 삭제·완료된 진행은 보존한다.

이 규칙은 이후 승인된 장에도 적용한다. 사건별 상황은 1인칭 현대인 독백 3~4문장, 선택은 `[즉시 행동] 속마음`, 결과는 실제 행동과 상대 반응을 담은 1~2문장으로 작성한다. 체력·자금 비용은 도입하지 않는다.

## 1. 5.1 동행과 지원 상태

새 전용 타입/효과 대신 기존 관리자 편집 가능한 `world.flags`를 사용한다.

- `chapter51AccompaniedCaoCao`, `chapter51AccompaniedLiuBei`: 실제 선택/동행 결과에서만 저장, 서로 배타적.
- 일반 관군·주민·황건 경로에는 두 값 모두 false/미정이다.
- 현재 `han`은 토벌군 측이라는 뜻이다. 지원 전 `factionId`를 조조·유비로 바꾸지 않는다. 지원 성공만 `factionId`와 soldier를 변경한다.

5.1 도입의 관군 합류 결과와 전선 사이에 관리자 편집 가능한 `han-company` 선택을 추가한다. 선택지는 유비 일행 동행, 조조 부대의 연락 임무, 일반 관군이다. 유비는 기존 탁군·청주 전선으로 연결하고, 조조는 조조 측 연락/후방 임무를 실제 행동으로 묘사한 별도 결과를 거쳐 중앙 전선 선택으로 이어 간다. **조조가 광종 전투를 지휘했다는 사실을 만들지 않는다.** 이는 게임상 연락 임무이며 실제 전선의 역사 배경과 분리한다. 조조 선택 후 다른 군주와 동행하는 선택을 다시 열지 않는다. 기존 `front`, `travel-north`, `travel-central`, 전투 ID는 보존한다. 일반 관군은 기존 전선 3개 중 선택한다.

더 간단한 구현이라도 반드시 명시적으로 고른 조조/유비 부대에서 실제 임무를 수행한 결과를 남겨야 한다. 지역·전투 승리·장수 이름이 단순 등장한 것만으로 동행을 추론하지 않는다.

`chapter-5-1-service/offers`의 `join-cao-cao`, `join-liu-bei`에 각각 해당 동행 flag=true 조건을 추가한다. 기존 위치·성인·생존·세력·포로 조건도 유지한다. 거절은 기존 `rejected-* -> travel` 연결을 유지하며 `travel`에는 185년 실제 사건 지역 양주(서방), 기주, 탁군이 표시된다. 해당 지역의 예정 사건/할 일을 설명에 명시한다. 다음 장들도 기존 목적지 목록이 실제 다음 장 사건 지역과 대응하는지 검사한다.

185년 이후에는 그 장에서 실제 동행/접촉한 군주 표식을 같은 원리로 기록하거나 기존 정식 소속 유지 경로를 사용한다. 지역만 같은 모든 군주에게 자동 접촉한 것으로 쓰지 않는다. 원래 소속의 유지/이탈은 별도 선택으로 유지한다.

## 2. 단일 기록과 역사 공개 시점

### 최소 데이터 확장

`RecordEntry`에 선택 필드 `recordType?: 'personal' | 'background' | 'outcome' | 'news'`, `recordId?: string`를 추가한다. 기존 kind는 호환용으로 유지한다. `FlowNode.data`의 result 노드에 선택 필드 `recordType?: 'background' | 'outcome' | 'news'`를 추가한다. 미지정 result는 개인 결과다. 새 필드는 `lib/event-flow-types.ts`, `validateFlow`, 관리자 노드 편집 UI에 함께 지원한다.

배경·결말·소식은 텍스트를 사건 summary에서 런타임 추측하지 않고 **그래프의 명시적인 result 노드**에 기록한다. `background`는 선행 세계 조건을 통과하여 해당 사건에 진입할 때 선택 앞에 딱 한 번 온다. 소속 이동 결과와 배경은 전선 도착 맥락을 잇는다. 비참가자는 현지인 독백을 읽지 않고 `news` 경로에서 해당 사건 소식을 받는다. 사라진 전투의 원래 전개를 배경으로 미리 확정하지 않는다.

`advanceFlow`는 기존 `results: string[]`와 함께 처리한 결과 노드의 id·text·recordType 목록을 반환한다. `getCurrentEvent`와 `resolveChoice`는 이 목록을 실행 순서로 `world.log`에 보존한다. recordId는 사건 ID + 노드 ID(선택 결과는 선택 키)로 안정적으로 만든다. 같은 커서·선택 키 재전송 시 중복·재보상이 없어야 한다.

선택 로그의 detail은 선택의 실제 개인 결과와 판정 서술을 담고, 별도로 기록한 배경/결말 문자열을 다시 합치지 않는다. 선택 결과 뒤 역사 결말이 실행되면 화면 순서는 개인 결과 → 역사 결말이다. 배경은 선택 이전에 공개한다. 노드가 여러 개 처리되더라도 순서는 보존한다. 원래 기록 재생의 커서/공개 상태를 사용하고 미래 결과를 화면에서만 가리지 않는다.

### 표시와 호환

`lib/history-records.ts`에 `unifiedRecords(world)` 순수 selector를 둔다. 기본 입력은 `world.log` append 순서이며 화면은 최신순으로 반전한다. 월이 없는 같은 해 사건을 제목/월로 다시 정렬하지 않는다. `historyLog`의 사건별 집계와 world.log를 둘 다 표시하지 않는다. world.log에 없는 옛 archive 사건만 fallback으로 표시하며 기존 로그나 결말을 만들어내지 않는다.

`kind==='history'`만으로 사료 원문이라고 표시하지 않는다. 기존 자동 로그에도 게임 창작이 섞여 있다. 새 recordType에만 배경/결말/소식의 짧은 표식을 표시한다. 완료 화면 Chronicle은 실제 저장된 진행을 사용하며 배경을 개인 공적으로 바꾸지 않도록 필터한다.

PC 레이아웃 예: 1440px에서 왼쪽 230px, 중앙 `minmax(320px,1fr)`, 오른쪽 `minmax(380px,1.1fr)`. 769~1000px는 좌측 정보를 압축하고 중앙/오른쪽이 최소 너비 아래로 내려가지 않게 조정한다. 오른쪽은 사용 가능한 높이를 채우고 내부 기록만 스크롤한다. 중앙에는 사건·선택/완료 연대기를 둔다. 모바일은 캐릭터 한 줄 → 현재 사건 → 기록 하나이며 기록 읽기 중에는 기존 재생 규칙대로 선택을 숨긴다. 두 패널 focus 토글·점프는 제거한다. 320px에도 가로 넘침이 없어야 한다.

### 역사 결말의 호환 기준

- 5.1 각 전투의 기본 결과 노드만 해당 사료 결말을 출력한다. capture·구출·대체 승리 노드에는 실제 대체 결과를 기록한다.
- 대흥산 황건 승리 후 청주 구원전 취소, 광종 보존 후 하곡양 공격 취소, 노식 지휘 유지, 포로 보호 성공은 각각 현재 세계와 맞는 문장만 출력한다.
- 승리 진영만 같아도 인물 생존·포로·지휘관 경로가 달라지면 전체 원래 결말을 출력하지 않는다. 승리·생존·지휘 모두 양립하는 부분만 쓴다.
- 5.2~5.5 이번 지원 임무는 전국 전역의 승패를 바꾸지 않는다. 개인 임무 실패와 NPC 전역 결과를 분리해서 적는다. 기존 world에 사망/패망/전제 불성립이 있으면 관련 NPC 임무·승리를 자동 강행하지 말고 조건 분기로 취소/변경 소식을 남긴다.

## 3. 사건 정보에서 조사 문구 분리

`data/collection/*.json`의 접근 실패·reviewStatus·sourceIds·dateNote 원자료는 관리자 근거로 보존한다. 원전 직접 확인했다고 올려 쓰지 않는다. 플레이어에게는 명확한 정사/연의/가상 분류, 깨끗한 사건 배경, 알려진 출처명만 보여 준다.

생성기에서 5.1 `source.record` 금지 접두어를 제거하고 관리자 근거는 수집본에 둔다. 후속 source.title의 `(2차 자료 요약·원사서 미대조)`도 플레이어 제목으로 쓰지 않는다. 플레이어 source modal은 `summary` 전체를 그대로 노출하지 말고 그래프 배경 노드·실제로 공개된 결과만 표시한다. `dateNote`의 자료 대조·연대 배치·동명이인 ID 해설은 관리자에 둔다. 소설/가상 시나리오라는 짧은 표시는 유지한다.

`narrative-5-1.json`, `campaign-narrative.json`, 생성기 기본 historical 결과에서 `수집본 기본 경과`, `원페이지`, `실행 경로`, `생존 판정`, `자료의 동명이인`, `중복 서술`, `기본 경과로 진행` 등 조사·엔진 해설을 일반 사건 문장으로 고친다. 완료/선택 팝업, 기록, 사건 정보에서 함께 점검한다. 기존 저장의 정확히 알려진 기본 접두어는 표시 단계에서 제거 가능하지만 임의 사용자 문장 전체를 광범위 정규식으로 잘라 버리지 않는다.

## 5. 이전 저장·관리자 편집 마이그레이션

구현 전에 현재 `events.json`을 별도 버전 파일로 보존한다(예: `data/history/legacy-campaign-v1.json`). 직전 기본본을 잃은 뒤 새 기본본과 비교하는 방식은 허용하지 않는다.

- `upgradeLegacyEvent`에서 id를 기준으로 **이전 기본값과 정확히 같은 필드만** 새 기본값으로 보완한다. 텍스트·조건·효과·연결·노드 위치는 각각 독립 비교한다. 사용자 편집 필드는 보존한다.
- 새 노드/선택은 안전한 기존 기본 연결에만 삽입한다. 사용자가 관련 연결을 바꾼 경우 전체 그래프를 기본본으로 교체하지 않는다. 사용자 삭제 노드/선택을 임의 복구하지 않는다. 기본 전체 그래프와 동일한 예전 그래프는 새 기본 그래프로 교체해도 된다.
- 이미 서비스/후속 사건이 있는 공유·로컬 편집본도 이번 업그레이드를 통과해야 한다. 현재 `upgradeLegacyCatalog` 조기 return은 필드 업그레이드 뒤에 적용한다. 명시적 deletedIds는 최우선이다.
- game persist v8. 과거 개인 선택에 새 `han-company:...`가 있으면 그 ID를 증거로 동행 flag를 복원한다. 이전 기본 북부 관군의 `han-plan`/`han-signal` 등 실제 유비군 행동 선택은 유비 동행의 근거가 될 수 있다. 반면 지역 jizhou만 있거나 조조 이름을 소식에서 읽은 것만으로 조조 동행을 만들지 않는다. 증거가 없으면 재야 목적지 선택만 제공한다.
- 이미 정식 합류한 factionId·성공 판정·진행 커서·능력치·턴·사망·지배·엔딩은 유지한다. 서비스 선택 이전 세이브에만 신규 제한을 적용한다. 이미 거절된 travel 커서는 즉시 목적지 선택에서 복원한다.
- 기존 historyLog는 삭제하지 않고 호환 archive로 유지할 수 있으나 unified selector에서 중복 출력하지 않는다. 이미 없어진 옛 로그는 새로 발명하지 않는다. 공개한 배경/결말을 새로고침 뒤 재생하지 않는다.

## 6. 의미 있는 검증과 완료 조건

기존 `lib/campaign-routing.test.ts`의 jizhou에서 두 군주 지원 성공을 가정한 fixture를 수정한다. 단순 노드 수 검사보다 실제 엔진을 끝까지 실행한다.

1. 신규 관군 → 조조 실제 연락/동행 → 5.1 완료: 조조만 노출. 유비 동행은 유비만. 일반 관군/주민/황건은 둘 다 숨김. 지역을 같게 강제해도 결과가 바뀌지 않음.
2. 각 군주 지원 성공은 매력 한 번 추첨·병사 소속·다음 활동지 저장. 실패는 무소속 + 185년 세 목적지 모두 노출, 선택 전 위치 유지, 선택 후 해당 지역/해 185/나이 21. 새로고침/선택 키 재전송으로 재판정하지 않음.
3. 죽은 군주·패망·포로·미성년·다른 지역은 동행 표식이 있어도 지원 숨김. 기존 정식 소속 유지/이탈은 정상.
4. 배경은 관련 장면 첫 선택 전에 한 번, 실제 결과는 행동 뒤. 황건 대흥산 승리 → 청주 취소, 광종 보존 → 하곡양 취소, 한충 구출, 노식 유지, 관군 통상 승리에서 모순된 승리/전사 문장이 없는지 확인.
5. 각 후속 16개 사건을 현지 재야/관련 소속/무관 소속으로 실행한다. 성공/실패 모두 후속 장면을 거쳐 종료하며 미리 결말을 스포일러하지 않음. 재야에게 군 내부 명령, 무관 소속 순간 이동, 죽은 지휘관이 없어야 함.
6. unified selector는 개인+배경+결말의 발생 순서·안정 키를 유지하고 같은 사건 완료 archive를 중복 표시하지 않음. 완료 전 자동 기록도 즉시 표시. save JSON roundtrip, 오래된 기록, 같은 해/월 미상도 순서 보존.
7. 이전 v7 부분 편집/전체 공유/완료 세이브, 신규 노드 중간 커서, 거절 뒤 travel 복원. 수정한 제목/문구/조건/배치와 명시 삭제 보존. 기본 수정은 새로고침 후 반영. 관리자에서 새 노드·recordType·조건·효과 편집 → 저장 → 새로고침 → 게임 반영.
8. 플레이어 전체 노출 문자열에서 금지 접두어·조사/엔진 해설 제거, 관리자 원자료의 출처·이견 유지. 가상 결말을 사료로 표기하지 않음.

실행: `npm run typecheck`, `npm test`, `npm run build`, `node scripts/validate-event-data.mjs`, `node scripts/validate-collected-chapter.mjs`, `node scripts/validate-campaign-data.mjs`. 생성기는 두 번 실행해 재생성 결과가 안정적인지 비교한다.

## 높은 추론 검증 기록 — 2026-10-20

구현 후 GPT-6.1 Sol 높은 추론 검증에서 초기 전체 테스트의 33개 실패를 확인했다. 군주 동행 선택과 접촉 조건이 추가되면서 바뀐 기존 fixture는 실제 새 선택을 거치도록 수정했다. 기존 검증의 생존·승패·중복 방지 의미는 유지했다. 새 동행 선택의 행동 이미지와 소속 유지 임무의 성장 연결 누락은 구현 결함으로 수정했다.

검증 중 발견해 수정한 실제 문제:

- 14개 후속 사건의 첫 상황이 같은 연락책 문장으로 반복되던 것을 사건별 갈등으로 다시 썼다. 첫 단계에서 이미 전달/대피를 완료하고 다음 단계에서 같은 일을 반복하던 왕분·장연·가룡·서원군 등의 결과를 준비/확인 → 실제 후속 행동으로 연결했다. 결과에 남아 있던 현재형도 고쳤다.
- 주요 연결 인물의 사망뿐 아니라 관련 세력 패망도 후속 사건의 전제를 검사한다. 같은 지역에 머무는 소속원은 다시 이동했다고 기록하지 않는다. 후속 장 접촉은 관련 군주 전원에게 저장하며 단순 지역 일치로 지원을 열지 않는다. 186년 재야 목적지에서 다음 사건이 없는 탁군을 제외했다.
- 5.1 통상 결말은 수집본의 깨끗한 사실 요약을 기록한다. 대흥산에는 유언군/유비 의용병의 승리, 정원지·등무 전사, 대군 와해·대규모 투항, 유비 삼형제의 첫 출전/승리를 포함한다. 광종은 아직 처리하지 않은 장보의 결말을 미리 확정하지 않도록 별도 사실 문장으로 썼다. 노식 유지·생포·구출 경로는 실제 다른 결과를 유지한다. 개인의 명령 수행 결과와 역사 결말의 사망 문장을 중복 기록하지 않는다.
- 하나의 선택 뒤 개인 → 역사 → 추가 개인 결과가 실행되는 관리자 그래프에서 마지막 개인 문장이 역사보다 먼저 표시되던 순서를 수정했다.
- 관리자 결과 문장을 바꿨는데 완료 연대기가 같은 노드 ID의 기본 사망 문장으로 요약하던 문제를 수정했다. 기본 결과와 텍스트까지 일치할 때만 기존 짧은 요약을 사용한다.
- eventId 이전 저장의 실제 로그와 복원 archive가 두 번 표시되던 문제를 수정했다. 일반 관군 선택이 명시되어 있으면 후속 유비군 지원 행동을 동행으로 잘못 추정하지 않는다.

`lib/campaign-itinerary.test.ts`의 13개 추가 시나리오는 단순 수량 검사 대신 다음 실제 경로와 결과를 실행했다.

- 조조 후방 연락 동행 → 광종·하곡양 진행 → 조조만 지원 → 정식 병사 → 185년 왕분 임무·매년 소속 유지 업무 → 188년 낙양 서원군 임무. 외지 미양 전투에는 이동하지 않는다.
- 유비 일행 동행 → 대흥산·청주 → 유비만 지원 → 정식 병사 → 소속 유지 업무 → 187년 안희 부임·관직 이탈 → 188년까지 소속 유지. 서방 전투는 소식으로 받는다.
- 실제 조조 동행 → 매력 0으로 거절 → 저장/복원 뒤 목적지 3개 유지 → 185년 서방의 양주(봉기·장수) → 186년 회계(하제) → 187년 장사(우성) → 188년 익주(마상·가룡, 이후 유언). 각 지역에서 두 단계 개인 행동을 거쳐 188년·24세까지 완주한다.
- 일반 관군의 지원 제한, 대흥산 통상 승리/수령 생포/황건 승리와 청주 취소, 노식 유지·장량 생포·장보 항복, 사망/패망 세계의 후속 전역 취소, 커스텀 결과 연대기, 관리자 문구·이미지·효과·조건·배치 보존, 혼합 기록 순서, 이전 기록 중복 방지를 확인했다.

최종 결과: 테스트 **26개 파일·224개 통과**, 타입 검사 통과, 실행 사건/수집 5.1/수집 5.2~5.5 검증기 3개 통과, `git diff --check` 통과. 생성기를 다시 실행한 `events.json`과 `officer-abilities.json`은 실행 전 SHA-256과 일치했다. 실행 로그는 `/tmp/rework-high-final.log`, 재생성 비교는 `/tmp/rework-high-hash-before`에 있다. 이 단계에서는 브라우저나 서버를 실행하지 않았으며 PC/모바일·관리자 브라우저 검증과 프로덕션 빌드는 상위 작업에서 별도로 확인한다.

이번 후속 사건의 개인 임무는 전역 전체의 승패를 바꾸지 않는다. 알려진 세부 전개는 사실 배경·후속 상황·결말로 분리하되 원자료의 모든 문장을 반복 출력하지 않는다. 새로운 역사 수집이나 원전 직접 대조를 수행한 것으로 보고하지 않는다.

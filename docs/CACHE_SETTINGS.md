# 테스트 캐시 설정

프로젝트 루트 `.env`의 기본값은 다음과 같다.

```dotenv
CACHE_ENABLED=false
CACHE_TTL_SECONDS=3600
```

- `false`: 페이지를 요청 시 렌더링하고 페이지·API·공개 이미지 응답을 저장하지 않는다. Next Image 최적화를 우회하고 `/title-screen.png` 원본을 직접 사용하므로 파일 교체 후 새로고침하면 반영된다.
- `true`: 공개 파일·API 응답의 브라우저 캐시 시간과 이미지 최적화의 최소 캐시 시간을 초 단위로 적용한다. 타이틀은 파일 내용에 따른 해시 URL로 제공한다. Next.js의 개발 페이지는 자체적으로 캐시를 제한하며, 운영 페이지의 생성·재검증 정책은 Next.js가 관리한다.
- `CACHE_TTL_SECONDS`: 0 이상의 정수. 캐시가 꺼져 있으면 적용하지 않는다. 이미지 최적화는 원본 응답의 시간이 더 길면 그 시간을 사용할 수 있다.

설정을 바꾸면 개발 서버를 다시 시작한다. 운영 서버는 다시 빌드하고 시작한다. `.env.local`에 같은 키가 있으면 해당 값이 우선한다. Firebase 설정은 기존 `.env.local`에 유지한다.

게임 진행·관리자 초안의 localStorage와 Firebase 인증 상태는 캐시가 아니라 저장 데이터이므로 삭제하지 않는다. Next.js의 해시가 붙은 JS·CSS 번들과 외부 글꼴 CDN의 캐시는 프레임워크·제공자가 관리한다. 이전 버전의 캐시가 이미 남았다면 적용 후 처음 한 번은 강력 새로고침한다.

## 자동 반영과 사건 공유본

`npm run dev -- --port 3001`에서는 코드·스타일을 저장하면 Next.js가 자동 컴파일한다. `npm run start`는 빌드된 운영 파일을 실행하므로 소스 수정만으로 바뀌지 않는다.

코드의 컴파일과 Firebase 사건 게시본은 별도다. Firebase가 설정된 게임은 공유 사건을 사용한다. 로컬 JSON만 수정했으면 생성·게시까지 해야 공유 게임에 반영된다. 현재 `CatalogProvider`는 `eventCatalog/current`의 리비전 변경을 실시간으로 감지한다. 편집하지 않은 목록은 새 게시본으로 갱신하며, 캐시 해제 상태에서는 Firestore의 서버 조회를 사용한다.

새 게시본이 있어도 로컬 사건 편집본은 자동으로 덮어쓰지 않는다. 이 경우 화면의 ‘최신 사건 적용’으로 명시적으로 교체한다. 게임 진행·이름·선택 기록은 유지한다. 이미 저장된 과거 결과 로그의 문구는 소급해서 변경하지 않는다. 브라우저가 새 코드에 연결되기 전부터 열린 화면이면 처음 한 번 새로고침한다.

실행 예시: `npm run dev -- --port 3001`. 확인 주소는 `http://localhost:3001/`이다.

# 모델 작업 방식

요청한 기본 순서는 GPT-6.1 Sol의 높은 추론으로 설계하고, 낮은 추론으로 구현한 뒤, 높은 추론으로 전체 상태 계약을 검증하는 방식입니다. 하위 에이전트는 추가로 생성하지 않습니다.

설계는 자료의 사실·월 정밀도와 게임 창작을 먼저 분리합니다. 구현은 확정한 상태 타입과 순수 함수 경계를 따릅니다. 검증은 타입·단위 테스트·프로덕션 빌드뿐 아니라 실제로 월별 선택과 연간 증가가 연결되는지, 세계 분기가 후속 사건의 전제와 모순되지 않는지 확인합니다. 모델의 자기 설명만으로 사용한 모델이나 검증 성공을 단정하지 않고 실행 결과를 기준으로 보고합니다.

이번 최종 검증은 GPT-6.1 Sol high 실행이 연속으로 서버 capacity 오류를 반환하여, 사용자 승인에 따라 GPT-6 Sol high로 이어갔습니다. 기본 모델 순서를 변경한 것은 아닙니다.

## 연표·장수 데이터 추가 작업

이번 요청은 low 작업 및 Gemini CLI 활용으로 별도 지정되었다. 추가 설계·검증용 high 에이전트를 실행하지 않았다. Gemini CLI의 실제 검토 모델은 `gemini-3.8-flash`이며, 웹 도구 오류로 공개 자료를 로컬 수집한 뒤 컬럼·수량·표본을 검토했다. CLI 직접 크롤링 성공으로 표시하지 않는다. 자세한 범위는 `REFERENCE_DATA.md`에 기록했다.

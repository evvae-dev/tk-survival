# Firebase 공유 사건 연결

연결 코드는 포함되어 있지만 실제 프로젝트 설정과 보안 규칙 배포가 필요합니다. 서비스 계정 비밀키는 브라우저에 넣지 않습니다.

## 연결 순서

1. Firebase 프로젝트에서 웹 앱을 등록합니다. `.env.example`을 `.env.local`로 복사하고 웹 앱 설정의 `apiKey`, `authDomain`, `projectId`, `appId`를 입력합니다. Vercel에도 같은 환경변수를 설정하고 다시 빌드합니다.
2. Authentication에서 Google 로그인을 켜고 `localhost`와 배포 도메인을 승인된 도메인에 등록합니다.
3. Cloud Firestore를 만들고 `firestore.rules`를 배포합니다. Firebase CLI를 사용한다면 `firebase deploy --only firestore:rules --project 프로젝트ID`를 실행합니다.
4. 관리자 페이지에서 Google 로그인 후 Firebase Authentication 콘솔에서 해당 계정의 UID를 확인합니다. Firestore 콘솔에서 `administrators/UID` 문서를 만들고 불리언 필드 `enabled: true`를 설정합니다. 이 문서는 웹 앱에서 작성할 수 없습니다. 로그아웃 후 다시 로그인하면 게시 권한이 반영됩니다.
5. `/admin/events`에서 편집 내용을 먼저 저장한 뒤 ‘저장된 목록 공유 게시’를 누릅니다. 이후 접속한 다른 브라우저의 게임과 사건 기록이 공유본을 불러옵니다.

## 저장 방식

각 게시본의 사건은 `eventCatalogRevisions/게시본ID/events`에 문서별로 저장합니다. 업로드가 끝나면 트랜잭션으로 `eventCatalog/current`를 교체합니다. 불완전한 목록은 플레이어에게 적용되지 않습니다. 다른 관리자가 먼저 게시했다면 게시를 거부합니다. JSON으로 로컬 편집본을 백업하고 공유본을 불러온 뒤 변경을 합쳐 다시 게시합니다.

브라우저에 미게시 편집이 있으면 자동으로 덮어쓰지 않습니다. ‘공유본 불러오기’는 로컬 저장 목록을 교체합니다. 열린 폼은 사건 목록에서 다시 선택해야 갱신됩니다. 게시에는 폼의 미저장 내용이 포함되지 않습니다. 같은 브라우저에서는 저장된 편집본을 게임으로 시험할 수 있습니다.

공유본은 접속 시 한 번 읽습니다. 이미 열려 있는 다른 브라우저는 새로고침해야 반영됩니다. Firebase 미설정 또는 읽기 실패 시 브라우저에 남은 목록을 사용하며 관리자 패널에 상태를 표시합니다. 과거 게시본과 게시 실패 시 남은 미참조 문서는 자동 삭제하지 않습니다.

## 권한과 검증 범위

사건 읽기는 공개이고, 쓰기는 관리자 UID 문서가 있는 로그인 계정만 가능합니다. 일반 이용자는 관리자 페이지 주소를 열어도 공유 게시 권한을 얻지 못합니다. 로컬 편집·시험은 가능하며 공유 게시와 별개입니다. 게시 전 사건과 그래프를 검사하고, 불러올 때도 전체 목록을 검사합니다.

실제 프로젝트 설정 없이 Google 로그인, 보안 규칙 적용, 서로 다른 기기 간 공유가 성공했다고 간주하지 않습니다. 프로젝트 연결 뒤 관리자 게시 성공과 비관리자 쓰기 거부를 각각 확인해야 합니다.

2026년 10월 15일 제공된 `tk-survival` 웹 앱 설정을 `.env.local`에 적용했습니다. 최초 서비스 비활성·권한 거부 상태를 해소하고 CLI 인증을 연결했습니다. 데이터베이스는 `(default)`, Standard, `asia-northeast3`입니다. 보안 규칙의 컴파일 검사와 실제 배포를 완료했고, 로그인한 프로젝트 관리자와 같은 Google 계정의 Firebase UID를 조회해 `administrators/UID.enabled: true`로 등록했습니다.

공유본이 없는 것을 확인한 뒤 기본 사건 289개를 관리자 IAM 권한으로 초기 등록했습니다. 게시 포인터는 기존 문서가 없을 때만 생성하도록 제한해 동시 게시가 있으면 덮어쓰지 않습니다. 새 브라우저의 앱에서 289개 불러오기와 계륵 사건 조회를 확인했습니다. 공개 읽기는 200, 인증 없는 쓰기는 403으로 차단됐고 검증용 문서는 생성되지 않았습니다.

브라우저의 관리자 화면은 새로고침하면 등록된 권한을 다시 읽습니다. 실제 사용자 로그인 세션의 ‘저장된 목록 공유 게시’ 버튼 동작과 인증된 일반 계정의 게시 차단은 추가 확인 대상으로 남습니다. 초기 등록은 관리자 IAM 경로이며, 브라우저 게시 경로의 실증과 혼동하지 않습니다.

로컬 기본 npm 캐시에서 CLI 의존성 누락이 발생해 별도 캐시를 사용했습니다. 이후 CLI 명령은 `npx --cache C:\dev\.codex\tmp\firebase-cli-npm-cache -y firebase-tools@latest`로 시작하면 됩니다. 인증정보는 프로젝트 소스나 환경변수에 복사하지 않습니다. `login:list --json`은 토큰까지 포함하므로 출력하지 않고 필요한 상태값만 추립니다.

# 이벤트 수집 규칙

2026-10-19 사용자 요청과 후속 변경을 정리한 상시 규칙이다.

**최신 확정:** Codex가 직접 수집한다(Gemini CLI 사용 안 함). 5.1~5.5 수집·플로우 연결이 승인됐다. 나무위키를 기본으로 상세 전개를 우선하고, 이견은 관리자 메모에 보존하면서 게임은 자연스럽게 연결한다. 아래 이전 절별 승인 규칙은 5.6 이후 별도 승인 범위에만 적용한다. 이 문서 저장만으로 새 수집이나 다음 절 진행을 시작하지 않는다. 기존 수집 완료 여부는 각 절의 작업 기록에서 확인한다.

## 기준과 역할

- 기준 연표: [나무위키 삼국지/연표](https://namu.wiki/w/삼국지/연표)의 **5. 본편**부터 시작한다.
- [사건 인과관계 설계](CAUSAL_EVENT_DESIGN.md)를 바탕으로 Codex가 사건별 수집 범위·필요 항목·관련 하위 절을 먼저 정한다.
- **페이지 크롤링·검색·사실 수집부터 검토·정규화·ID 연결·게임용 가공까지 Codex가 직접 담당한다.** 이전 Gemini 실행 기록은 과거 이력으로만 남긴다.
- 사실 수집과 게임 문구 작성은 구분하며, 게임 문구에는 [이벤트 작성 지침](EVENT_WRITING_GUIDE.md)을 적용한다.

## 범위와 제외 항목

- **독립적인 인물 탄생·사망 이벤트는 제외한다.** 전투 전개·결과를 이해하는 데 필요한 전사·생존·포로 정보는 해당 사건 안에 보존한다.
- 연표의 사건을 식별한 뒤, **해당 사건의 상세 서브링크로 들어가** 이벤트에 필요한 내용을 수집한다. 연표의 한 줄 요약만으로 상세 수집을 완료하지 않는다.
- 평가·기타 창작물에서의 등장 등 게임 사건의 실제 전개와 무관한 절은 제외한다.
- 오두미교·흑산적 등 문서에 함께 등장하는 링크를 무조건 따라가지 않는다. 현재 사건에 필요한 링크와 절만 지정한다. 이후 별도 사건으로 승인받을 가능성까지 영구 제외하는 뜻은 아니다.
- 연표의 절 번호·제목과 실제 상세 문서의 절 번호·제목을 조회 시 확인한다. 페이지 개편으로 대응이 모호하면 사용자에게 묻는다.

## 지정된 사건별 수집 경로

### 5.1 황건적의 난

[황건적의 난](https://namu.wiki/w/황건적의%20난) 상세 문서에서 다음 다섯 전투만 상세 수집한다.

| 하위 절 | 사건 |
|---|---|
| 4.1 | 대흥산 전투 |
| 4.2 | 청주성 전투 |
| 4.3 | 완성 전투 |
| 4.4 | 광종 전투 |
| 4.5 | 하곡양 전투 |

황건적의 난이라는 상위 사건군에 속하더라도 각 전투를 별도 사건으로 식별하고, 각자의 본문 근거·전개·결과를 연결한다. 작업 기록과 데이터 위치는 [5.1 수집 문서](COLLECTION_5_1.md)를 참조한다.

### 5.2 양주의 난

이번에 승인된 5.2 작업은 [양주의 난](https://namu.wiki/w/양주의%20난) 상세 문서에 들어가 이벤트 설계에 필요한 범위를 정하고 수집한다. 5.5까지 이번 사용자 승인 범위 안에서 연속 진행한다.

### 상세 서브링크가 없는 사건

- 예: 연표 5.8의 **대곡 전투: 손견(勝) vs. 동탁(敗)**.
- Codex가 해당 사건의 **전투 개요·배경·전개·결과**를 검색·조회를 수행한다. 관련 전투 문서 등에서 확인한 근거와 확인하지 못한 정보를 함께 받는다.
- Codex가 결과를 이벤트 데이터 형식으로 다시 가공하고 해당 사건에 연결한다. 인접 전투의 정보를 대상 사건의 정보로 잘못 옮기지 않는다.
- 사용자가 제시한 191년·손견 대 동탁·양인 전투 이후 대곡 격파·후퇴와 낙양 진격 설명은 조사 방향을 보여 주는 **참고 예시**다. 실제 수집 시 사실별 근거와 조회 여부를 확인하며, 예시나 Gemini 답변만으로 검증 완료 처리하지 않는다.
- 이 예시는 5.8 수집을 지금 승인한 것으로 해석하지 않는다.

## 사건별 필수 수집 항목

Codex는 아래 항목을 기준으로 직접 수집 범위를 정한다. 자료에 없는 값은 미확인 또는 `null`로 남기며 임의 보충하지 않는다.

1. 사건명·사건 ID·상위 사건군·기존 연표/사건 대응 ID.
2. 발생 연월·날짜 정밀도·시기 이견.
3. 지역·전장·확인된 이동 경로.
4. 참가 세력·인물·지휘관 및 각자의 역할.
5. 배경·목표·개요.
6. 단계별 전개: 행위자·행동·상대 반응·장소·전제·성패·앞뒤 관계.
7. 결과: 승패·생사·포로·소속·지휘권·지역 점유 등 실제 변화.
8. 후속 사건에 영향을 주는 상태와 선행·후행·대체·차단 연결 후보.
9. 정사·연의 등 자료 유형, 근거 문헌과 한국어 요지, 직접 원전 대조 여부.
10. 조회한 페이지·절·접근 성공 여부, 정보별 근거, 이견·미확인 사항·사용자 질문.

플레이어 개입·선택·능력 판정·가상 결과는 Codex가 사실 검토 뒤 별도로 설계한다. 창작 대화·속마음·가상역사를 역사 기록으로 저장하지 않는다.

## 사건별 연결과 근거 검토

- 각 사건은 해당 사건의 상세 자료와 연결한다. 상위 문서 URL 하나를 여러 사건의 개별 근거 대신 사용하지 않는다. 동일 페이지 안에 있는 사건도 해당 절을 구분한다.
- 인물·지역·세력은 기존 ID에 대응시키고, 동명이인이나 불명확한 대응은 사용자에게 묻는다. 기존 사용자 확정 연결을 임의 변경하지 않는다.
- **사건 내부 전개**와 **사건 간 인과관계**를 구분한다. 연표에 나란히 있거나 같은 해에 발생했다는 이유만으로 필수 선행 관계를 만들지 않는다.
- 연결에는 근거·방향·의미를 남기고, 미확정 연결은 후보로 표시한다. 독립 전장을 억지로 직렬 연결하지 않는다.
- 사이트 URL·절은 조사 메타데이터로 보존한다. 문헌 출처와 원사서 검증 상태는 별도로 기록하며, 나무위키 요약을 원사서 직접 대조 기록으로 표시하지 않는다.
- 웹 도구의 실제 응답과 본문 내용을 확인한다. 접근 오류·CAPTCHA·검색 요약만으로 본문 수집 성공을 선언하지 않는다. 접근 제한을 우회하지 않는다.

## 진행·질문·완료 규칙

1. **5.1부터 절 단위로 진행한다.** 기존 자료가 있으면 먼저 대조하여 중복 사건·중복 실행을 방지한다.
2. 모르는 사실·애매한 항목·범위 판단·동명이인 등은 사용자에게 질문한다. 답변이 필요한 부분을 임의 확정하지 않는다.
3. 각 절 완료 시 수집한 사건, 사건별 연결, 제외 항목, 미확인 사항, 저장 위치와 검증 범위를 보고한다.
4. **현재는 5.5까지 수집·연결을 연속 진행한다. 5.6 이후는 사용자에게 진행 여부를 묻는다.** 최신 승인 범위가 이전 절별 중단 규칙보다 우선한다.
5. 수집본 저장, 게임용 가공, 관리자 등록, 공유 게시를 구분해 실제 완료한 범위만 보고한다. 실행 사건을 추가하는 단계에서는 이벤트 작성 지침의 관리자 등록·편집 보장 기준도 충족한다.

## 사이트 이용 규칙 확인

실제 수집 전에 Codex의 웹 조회 도구로 현재 적용되는 `robots.txt`, 이용약관과 재사용 라이선스를 확인하고 확인 결과·접근 한계를 기록한다. 요청 간격과 재시도 횟수를 제한하며 불필요한 재조회·링크 전체 순회를 피한다. 이 문서는 나무위키의 현행 정책을 직접 확인했다는 기록이 아니다.


## 합류·진행·출처 귀속 (최신)

- 어느 장이든 상황상 만날 수 있는 군주급 인물에게 합류 기회를 제공한다. 5.1은 조조·유비, 후속 장은 동탁·공손찬 등 현재 위치와 시대에 맞게 정한다.
- 합류는 매력 확률 판정이며 성공·거절과 실제 소속·역할 변화를 기록한다. 이미 죽은 군주나 패망한 세력, 만날 수 없는 지역에는 지원 선택을 열지 않는다.
- 소속 유지 시 해당 세력의 활동지·사건을 따라간다. 관련 없는 타 세력 전투에 순간 이동시켜 참가시키지 않는다. 재야는 다음 장의 활동 지역을 직접 고른다.
- 발령자·상위 세력·현장 지휘관을 구분한다. 나중에 휘하가 된 장수의 이전 전공을 그 군주의 지휘로 소급하지 않는다.
- 사료 이견이 있어도 일관된 기본 게임 전개를 정한다. 실제로 확인하지 못한 항복·생사·승패를 확정 효과로 만들지 않는다. 게임상 보완한 이동·지원·대화는 창작으로 분리한다.
- 나무위키 원사이트 접근 실패는 실패로 남기고, 공개 미러를 읽었다면 실제 URL·문서 절·라이선스·원사이트 미열람을 기록한다.

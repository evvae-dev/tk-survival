# 5.1 실행 사건과 분기

2026-10-16 현재 개발 기준이다. 이전의 170~190년 무작위 시작·10세 성장·280년 진행은 폐기하고 **184년·20세 고정 테스트**로 전환했다. 다음 5.2 수집은 사용자 확인 후 진행한다.

## 활성 데이터

| 용도 | 파일 | 수량 |
|---|---|---:|
| 수집 사실·원페이지 이견·18단계 전개 | `data/collection/5-1-yellow-turban.json` | 전투 5개 |
| 게임과 사건 관리가 함께 사용하는 실행 그래프 | `data/history/events.json` | 사건 7개 |
| 수집본과 연결된 상위 연표 | `data/reference/chronology.json` | 기록 6개 |
| 장수 기준 자료 | `data/reference/officers.json` | 1,000명 |

실행 사건은 `chapter-5-1-opening`, 전투 5개, `chapter-5-1-closing`이다. 이전 기본 사건과 공유 사건은 현재 목록에서 모두 제거했다. 기존 RTK14 이벤트 참고 목록도 활성 데이터에서 제거했다. 과거 문서의 사건 수·연도·모델 작업 기록은 당시 작업 기록이며 현재 구현과 구분한다.

수집 JSON의 `playable: false`는 **원자료 자체를 직접 실행하지 않는다**는 뜻이다. 실행 분기는 별도 `events.json`의 `flow`에 있다. 출처 미확인 사서명·원문을 새로 만들지 않았고, 광종·하곡양의 장보 결말 중복과 월 표기 이견도 원자료에 남겼다. `metadata.referenceFileHashes.chronology`는 수집 당시 전체 연표의 해시이며, 활성 범위 정리 이후에는 현재 6개 연표와 동일한 파일 해시가 아니다. ID 참조를 검증하며 장수 파일 해시는 계속 검사한다.

## 플레이 방식

이름 입력 후 184년·20세로 시작한다. 출생 지역과 농민·상인·서생·군인·사족 가정은 무작위다. 통솔·무력·지력·정치·매력의 기본값 50에 가정 보정을 더한다. 체력·자금은 사용하지 않는다. 군인은 통솔·무력, 서생은 지력·정치, 상인은 매력, 사족은 지력·정치·매력에서 차이가 난다.

첫 사건에서 관군·황건군·주민 중 진영을 고르고 탁군/청주, 남양/완성, 광종/하곡양 중 전선을 고른다. 이동 비용은 없다. 이번 테스트는 한 전선에서 행동한다. 확정되지 않은 전선 사이의 월·이동 시간을 만들어 모든 전투에 순간 이동시키지 않는다.

사건 안의 선택마다 `turn`은 선택 횟수로 증가한다. 연도와 나이는 유지하며 연간 성장 선택은 없다. 참가하지 않은 전선도 원자료의 기본 전개와 앞선 세계 상태에 따라 처리된다. 모든 전선을 처리하고 결말에서 기록을 확인하면 종료한다.

## 전투별 분기

| 사건 | 관군 | 황건군 | 다음 사건에 미치는 영향 |
|---|---|---|---|
| 대흥산 · 연의 | 등무와 일기토 또는 정원지와 전투 판정으로 생포 | 유비와 전략·전투 판정으로 매복·구출 | 관군 진격 성공 때만 청주 구원전 성립 |
| 청주성 · 연의 | 전략 신호 조율 또는 전투 돌격 | 유비와 전략·전투 판정으로 유인 간파·봉쇄 | 청주성 지배·황건 거점 존속 |
| 완성 · 역사 계열 | 조홍과 전투, 한충과 정치 협상 뒤 매력으로 포로 보호 | 주준과 전투·전략 판정으로 방어·대피 | 완성 지배·한충 등 생존·포로 보호 |
| 광종 · 역사 계열 | 정치로 노식 교체 저지, 장량과 전투 판정으로 생포 | 황보숭과 전투·전략 판정으로 야습 저지·구출 | 광종 점령 때만 하곡양 후속 공격 성립 |
| 하곡양 · 역사 계열 | 장보와 전투·관계 판정으로 생포·항복 | 황보숭과 전투·전략 판정으로 돌파·대피 | 장보 생존·거점·황건 주력 존속 |

주민은 매력으로 피란로를 열거나 지력으로 구호 물자를 확보한다. 구호 성공은 주민 보호 표식으로 남으며 전장 승패는 기본 경과를 따른다. 능력 판정은 선택할 때 한 번 추첨한다. 상대 장수가 있으면 `50 + (내 보정치 - 상대 보정치) × 가중치`, 없으면 능력치%를 적용한다. [능력 확률 판정](ABILITY_CHECKS.md)에 계산·설정·저장 계약을 정리했다. 판정과 대체 결과는 게임 창작이다.

전장 지배는 `place-daxingshan`, `place-qingzhou-city-novel`, `place-wan`, `place-guangzong`, `place-xiaquyang` 단위다. 완성 하나의 점령을 형주 전체 점령으로 처리하지 않는다. 전선 배치 지역은 여전히 상위 지역 ID를 사용한다.

## 인물과 인과 상태

- `world.people[personId]`: 생존 또는 사망. 이미 사망한 인물에 생존 효과를 적용해도 부활하지 않는다. 포로·피신 등 구체적 결말은 세계 표식과 기록으로 구분한다.
- 연결된 인물은 `person-rtk14-…` ID를 사용한다. 조홍은 사용자 지정 `rtk14-0620`, 한충은 `rtk14-0173`이다. 손하(孫夏)는 미확인 장수 `rtk14-0543`과 연결하지 않고 수집 인물 ID를 유지한다.
- `world.flags`: 전선 승패, 수령 생포·피신, 주민 구호, 노식 지휘 유지, 후속 공격 취소 등. 뒤 사건의 조건 노드가 직접 검사한다.
- 광종의 장보 결말 중복은 사실 수집본에 남기되, 기본 실행에서는 장보의 사망을 하곡양에서 한 번 적용한다. 먼저 장보가 사망한 편집 경로에서는 하곡양 전투가 취소된다.
- `prerequisiteEventIds`: 선행 사건 처리 제약. `sequence`가 바뀌어도 선행 사건부터 처리한다. 사용자가 삭제한 선행 사건은 실행 제약에서 제외한다. 순환 의존은 저장·게시에서 거절한다.
- `connections`: 사건 간 그래프의 연결·설명. 실제 개방·취소 판정은 내부 조건 노드와 결과 효과에 있다. 연결선만 바꿔서는 세계 판정이 바뀌지 않는다.
- `appliedEventIds`와 선택 커서로 사건·결과 중복 적용을 막는다. 참가하지 않은 전선 결과도 결말 선택 시 함께 저장한다. 예전 연도별 세력 자동 생성·강제 멸망 코드는 제거했다.

## 관리자 화면

`/admin/collection`의 기본 탭 **게임 실행 플로우**에서 사건 간 연결을 본다. 사건을 두 번 누르거나 왼쪽 목록에서 고르면 내부 조건·선택·결과가 나온다. 노드 바로가기로 확대하고 오른쪽에서 판정과 효과를 읽을 수 있다.

**이 사건의 노드·조건·선택·결과 편집**을 누르면 `/admin/events?event=…` 편집기로 이동한다. 여기서 노드·선택·연결을 추가·삭제·변경하고 ‘흐름 저장 · 게임 반영’한다. 사건 속성에서는 실행 순서·선행 사건 ID·사건 간 연결도 수정한다. 조건은 인물 생존과 지역 지배를, 효과는 인물 생존과 통솔 증감을 지원한다. 선택 노드의 상황 대사도 수정할 수 있다.

**수집 원자료 전개** 탭은 수집 당시 사실·출처·개입 후보를 보여 주는 조회 화면이다. 실행 편집과 수집 근거를 분리해 보존한다. 공유 반영은 관리자 로그인 후 Firebase 게시를 사용한다. 이미 해결한 사건은 재실행하지 않으므로 분기 편집을 시험할 때 새 게임을 시작한다.

## 저장·공유 전환

- 게임 persist 버전은 5다. 버전 4의 5.1 진행은 유지하며 정치 능력을 보충한다. 버전 3 이하의 이전 연간 성장 세이브는 초기화하고 이름 입력부터 다시 시작한다.
- 사건 브라우저 키는 `tk-survival-event-catalog-5.1-v1`, 동기화 키는 `tk-survival-catalog-sync-5.1-v1`이다. 이전 브라우저 편집본을 자동 병합하지 않는다.
- 이전 JSON을 가져와 삭제 사건을 되살리지 않도록 현재 장 ID가 다른 사건과 실행 그래프가 없는 사건을 거절한다.
- Firestore의 `eventCatalog/current`가 가리키는 새 리비전에는 실행 사건 7개만 있다. `referenceCatalog/current`는 연표 6개·장수 1,000명이다. 이전 리비전은 복구 이력으로 보존하지만 현재 게임과 관리자 목록에서 읽지 않는다.
- 전환 전 백업은 저장소 밖 `C:/dev/.codex/tmp/tk-survival-before-5-1`에 있다. 인증정보는 포함하지 않는다.

## 재생성과 검증

`node scripts/build-chapter-5-1.mjs`는 수집본과 작성한 분기 설계에서 기본 실행 JSON을 생성한다. **관리자 편집본을 소스 기본값으로 병합하는 명령이 아니므로 실행 전에 편집 내용을 JSON으로 백업한다.** 이전 전체 연표 수집기는 현재 범위에서 덮어쓰지 못하도록 차단했다. 5.2 수집은 Gemini CLI로 지정 본문만 조회하고 별도 장 자료로 추가한다.

```bash
node scripts/validate-event-data.mjs
node scripts/validate-reference-data.mjs
node scripts/validate-collected-chapter.mjs
npm run typecheck
npm test
npm run build
```

검사 범위는 실행 그래프, 성공·실패와 후속 사건 취소, 포로 생존, 사망 인물의 등장·부활 차단, 3개 진영×3개 전선×2개 능력 수준의 종료, 중복 선택·커서 복원·공유 저장 계약이다. 원사서 정확성 검증과는 구분한다.

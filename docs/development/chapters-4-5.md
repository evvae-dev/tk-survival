사용자 요청: 완료된 1~3화 푸시, 4화 완료 후 5화 개발, 전체 완료 후 재푸시. `origin/main` 푸시는 Vercel 자동 배포를 시작한다. Firebase 공유 카탈로그 게시와는 별도다.

- 시작 원격 main: `f26334b`. 원격의 120개 원본 챕터와 편집 스킬을 보존하며 리베이스했다. 1~3화 원본 충돌은 말미 빈 줄뿐이었고 원격 원본을 유지한 뒤 사실 SHA를 재생성했다.
- 1~3화 푸시 완료: `f401891`, `main`. 강제 푸시 없음.
- 개발 스킬: `.agents/skills/three-kingdoms-development/SKILL.md`, 실행 흐름·QA·화면 검증 스킬 적용.
- 4화 원본: `docs/romance-three-kingdoms/chapters/004.md`, 여덟 주요 전개.
- 5화 원본: `docs/romance-three-kingdoms/chapters/005.md`, 아홉 주요 전개. 4화 완료 뒤 구현한다.

## 4화 — 완료

- 사건 `r004-01`~`r004-08`. 3화 하진/정원 생존으로 독립 군영이 남을 때 폐립 보류가 가능하고, 이후에는 폐제 독살 장면을 재생하지 않는다.
- 거울 경고·성문 추격 지연·왕실 일가 생존·여백사 일가 구출과 진궁 동행을 후속 장면에 연결한다.
- 재야 초면은 소개, 접촉한 재야는 매력으로 정식 임관, 기존 소속은 유지한다.
- 완료한 1~3화 저장은 자동 변경하지 않고 ‘새 화 이어하기’를 눌러 계속한다. 과거 판단·능력·소속·인물 상태를 보존하고 전사/처형/통일 엔딩은 열지 않는다.
- 초기 실행 QA에서 지원하지 않는 null 조건 값을 확인해 기존 지원 문법인 소속 목록 조건으로 수정했다. 1~3화만 허용하던 연표 테스트는 현재 등록 챕터와 비교하도록 갱신했다.

- 문구·분기 QA: 14개 장면 평균 8.3점, 모든 장면 7점 초과. `data/chapters/chapter-004-qa.json`.
- 전체 13개 파일·122개 테스트 통과(`/tmp/tk-chapter4-final-tests.log`), 별도 타입 검사·프로덕션 빌드 통과(`/tmp/tk-chapter4-typecheck2.log`, `/tmp/tk-chapter4-build3.log`), 사건·참조 검증기 통과.
- 새 이미지 3개 실제 생성·직접 열람·연결: `r004-petition.png`, `r004-mirror.png`, `r004-pig.png`. 기존 일반 자산은 문맥에 맞게 재사용했다.
- PC 1440×1000, 모바일 390×844, 짧은 PC 1440×720에서 조건별 14개 장면을 모두 방문했다. 이미지 로드·선택 3개·가로 넘침·브라우저 오류 0건. `/tmp/tk-story-004/report.json`.
- 관리자 문구와 A/B 판정 안내 각각 편집→저장→새로고침→게임 반영 통과. `/tmp/tk-story-conditions-004/report.json`.
- PC·모바일에서 실제 3화 완료 저장의 상태 유지, 이어하기 클릭, 4화 진입, 새로고침 보존 통과. `/tmp/tk-story-continuation/report.json`.

- 알려진 미해결 오류 없음. 4화 완료 후 5화 구현 시작.

# 재생·이미지·판정·명성 규칙 개편

## 사용자 요청과 범위

1~5화 작업본 전체에 새 규칙을 적용한다. 기존 1~4화 공개본 HEAD는 `2fb0dd9`이고 이 기록 시작 시 5화는 새 이미지 생성 실패 때문에 미공개 상태였다. 이 작업은 새 요청의 구현을 계속하며, 기존 완료 기록·선택·판정·명성을 소급 변경하지 않는다.

## 구현

- 기록 기본 간격 5,000ms. 긴 본문에 따라 대기 시간을 늘리던 로직을 제거하고 타자 표시도 해당 기록 간격 안에 끝나도록 제한했다. 완주 연대기의 기본 간격도 5초다.
- 선택 직후 실제 선택 결과와 그림·명성 증감을 보여 주는 전용 카드를 표시한다. `pendingResult.recordId/expiresAt`를 저장해 재생 속도·문장 길이·재전송·새로고침에 시간을 다시 시작하지 않는다. 4,999ms까지 유지하고 5,000ms에 다음 카드로 전환한다. 전사도 결과 5초 후 최종 화면을 연다.
- 모든 선택 팝업은 옵션별 이미지를 유지한다. 중복을 이유로 이미지를 전부 숨기던 동작을 제거했다. 관리자 ‘이미지 없음’ 선택을 제거하고 인물 단독 경로를 거부한다. 이전 편집본은 해당 이미지/누락된 새 판정 필드만 보완해 문구·배치·연결·명시 삭제를 보존한다.
- `check.weights/difficulty`로 150개 판정의 비중과 난도를 명시했다. 단일 매력%·지력%를 일괄 적용하지 않는다. 증거 준비·정식 임관·보급·교섭·일기토 등 방법과 현재 조건에 따라 달라진다. `data/chapters/balance-review.json`에 판정별 근거를 보존했다.
- 성공 명성은 접촉 4점 안팎부터 정국·전투를 크게 바꾸는 30점까지 차등 부여한다. 실패는 성공 보상의 정확히 −50%다. 음수와 소수점을 허용하고 사망 결과도 차감한다. 판정 없는 대기는 0이며, 재제출·저장 복원으로 중복 지급하지 않는다.
- 게임은 실제 확률·성패별 명성 변화를, 관리자는 비중·상황 난도·성공 보상·근거 입력을 제공한다. 기존 장수 능력은 바꾸지 않았다.

## 이미지 생성·검수

선택 장면 75개와 옵션 225개, 총 300개 이미지 연결에 환경이 있는 장면을 사용한다. 단독 인물 경로 15개 원본 지정(상속 포함 21개 장면)을 제거했다. 생성 서비스의 초기 `Unknown parameter: reasoning` 오류는 복구됐고 새 자산 11개를 실제 생성·직접 열람·연결했다.

- 환경 장면 9개: 동탁 지휘부·전투 뒤 군영·왕실 영접 길·조조 경고·여포의 야간 막사 접근·손견 보급·화웅 도전·삼영전여포·동탁군 전선 연락소.
- 손견·화웅 기준 이미지 2개: 생성 참조로만 사용하며 게임에는 환경 장면을 표시한다.
- 삼영전여포 첫 생성본의 보병 표현은 네 장수의 기마전으로 수정했다. 생포·도주·승패를 선택 전에 확정하지 않는다.
- 야습·관문 지도·후퇴 수레처럼 문맥이 정확한 기존 환경 장면은 유지했다. 동탁군 시점에 연합군 주인공 이미지를 넣지 않는다.
- 실제 파일 SHA-256과 연결은 `data/chapters/artwork-manifest.json`, `data/chapters/image-rules-audit.json`에 기록했다.

## 검증

- 단위·실제 엔진: 전체 15개 파일·153개 테스트 통과(`/tmp/tk-rules-final-tests.log`). 모든 150개 판정의 실패 명성 차감, +7/−3.5, 음수, 전사, 준비 증거의 확률 차이, 편집본 보존, 중복 이미지 표시, 저장한 결과 기한을 검사했다.
- 프로덕션 빌드: `/tmp/tk-rules-build5.log`. 5초 타이밍·명성 UI의 최초 브라우저 검증은 `/tmp/tk-game-rules/report.json`; 4,999/5,000ms, 속도 변경, 새로고침, −2.5, 전사 결과와 관리자 편집→저장→새로고침→게임 반영을 통과했다.
- 모바일 결과 상단이 고정 헤더에 가리는 문제를 직접 캡처에서 확인해 스크롤 여백을 수정했다. 마지막 브라우저 검증은 그 수정 뒤 빌드에서 재실행한다.
- 검증 중 제가 프로덕션 서버가 동작하는 상태에서 빌드를 갱신해 2~5화 일부 검사가 새 정적 파일을 찾지 못했다. 이 결과를 제품 검증 통과로 쓰지 않는다. 빌드 완료 뒤 서버를 재시작해 영향받은 검사를 전부 다시 실행한다.

## 최종 검증 기록

최종 빌드 `/tmp/tk-rules-release-build.log`, 전체 153개 테스트 `/tmp/tk-rules-release-tests.log` 통과. 사건·참조 검증기 통과, 6개 생성 산출물 재생성 SHA-256 일치(`/tmp/tk-rules-release-regeneration.json`). 브라우저 최종 실행 결과는 아래에 이어 기록한다.

초기 생성 실패와 중간 빌드 중 정적 파일 불일치는 과거 진단 기록이다. 생성 복구 뒤 실제 신규 자산과 안정된 최종 빌드를 사용해 재검증한다. 과거 화별 편집 점수는 당시 판본의 기록이고 새 규칙 실행 근거는 이 문서와 새 테스트 결과다.

- 최종 PC·모바일 타이밍·보상·관리자 검증 통과: `/tmp/tk-release-rules/report.json`. 4,999ms 유지/5,000ms 전환, 속도 변경, 2.5초 뒤 새로고침 시 남은 시간 보존, +16/−8, −2.5, 전사 −12 및 결과 후 종료, 비중·난도·보상 편집 저장·게임 반영을 확인했다. 모바일 성공·전사 결과 캡처를 직접 열람해 헤더 가림·내용 잘림이 없음을 확인했다.
- 브라우저 동시 시작 중 시험 시계가 이미 지난 시각에 정지하려는 테스트 초기화 오류가 있었다. 빈 페이지에서 미래 시각에 정지한 뒤 기준 시각을 설정하도록 시험 도구를 수정했다. 최종 재실행을 통과했고 제품 판정·타이머 코드는 변경하지 않았다.

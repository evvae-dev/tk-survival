# 5.1~5.5 사건 연속성과 사실 기록 — 2026-10-20

이번 사용자 지시는 이전 `RECORD_AND_CAMPAIGN_REWORK.md`의 연간 소속 유지 업무·연례 선택·외지 사건별 소식 표시보다 우선한다. 높은 추론 설계와 이후 구현·검증 근거를 함께 보존하며 실행 결과는 아래 검증 기록을 따른다.

## 문제와 완료 계약

현재 `campaign-flows.mjs`는 모든 사건을 순서대로 처리하며 외지 사건마다 `remote-news`를 출력한다. 소속원도 매년 `stay-or-leave`와 명부/주민 업무를 반복한다. `event-engine.ts`는 해가 바뀔 때 같은 문장을 한 번 더 추가한다. 이 때문에 동탁을 따른 플레이어는 미양·한수라는 자신의 흐름 사이에 무관한 지방 기사와 가짜 일거리를 읽는다. 단순 문구 치환이나 화면에서 숨기는 방식으로 끝내지 않는다.

- 정식 소속은 이탈·패망 등 실제 변화가 있을 때까지 지속한다. 해가 바뀐다는 이유로 다시 묻거나 일을 만들어 주지 않는다.
- 사실 기록의 배경/결말/소식에는 웹소설 장면 제목을 반복 표시하지 않는다. 날짜·짧은 유형 표시와 **독립적으로 이해할 수 있는 완결된 문장**을 표시한다. 개인 행동은 기존 선택 제목을 유지할 수 있다.
- 사실 기록은 누가 어디서 무엇을 했으며 무엇이 달라졌는지 알려 준다. `폐위 모의가 실패했다`, `관군의 완전한 승리. 전원 사망` 같은 제목 의존 문장·명사형 나열은 쓰지 않는다. 예: `왕분 일행이 영제를 폐위하고 합비후를 세우려 했으나, 영제의 순행이 취소되고 군대 해산 명령이 내려지면서 계획은 무산됐다.`
- 플레이어가 참여하거나 현재 소속·지역·앞선 사건에 실제로 관련된 사건만 읽는다. 연표에 있다는 이유만으로 각지의 사건을 전부 개인 기록에 배달하지 않는다. 사실 원자료와 관리자 사건 목록은 모두 유지한다.
- 소속의 실제 이동과 다음 갈등을 관련 장면의 진입문에서 연결한다. 이미 같은 거점이면 이동했다고 반복하지 않는다. 사료에 없는 정확한 월·행군·전국 승패를 만들지 않는다.
- 5.5 범위가 끝나면 소속·위치·마지막 실제 활동과 남은 상황을 이해할 수 있는 결말을 준다. `현재 사건 목록의 진행을 마쳤습니다`를 게임 본문으로 사용하지 않는다. 5.6의 새 역사 사건이나 전투를 수집·발명하지 않는다.

## 최소 실행 구조

기존 28개 사건과 연도별 선행 사건 순서는 유지한다. 순서 제약은 처리 순서이며 플레이어에게 보여 주는 서사가 아니다.

### 외지 사건의 조용한 처리

`collectedEvent`에서 현재 소속에 관계없고 현지에도 없는 경로는 `remote-news` 결과 대신 바로 `end`로 간다. `getCurrentEvent`는 이 사건을 정상 완료하여 applied/resolved에 넣되, 빈 로그·자동 재생 카드·집계 archive를 만들지 않는다. 현재 후속 사건의 외지 경로에는 reported flag 이외 세계 효과가 없으므로 소식 한 건을 건너뛴다고 역사 생존 상태를 잃지 않는다. 향후 명시적인 세계 효과가 있는 사건은 해당 효과를 실행하되 노출과 별개로 취급한다.

관련성은 먼저 기존 그래프의 `allegiance`, `local`, `independent` 조건으로 판정한다. 새 런타임 전용 숨은 선택 시스템을 도입하지 않는다. 의미 있는 외지 소식이 필요하면 명시적 조건과 사실 문장을 가진 `news` 노드로 작성한다. 예를 들어 북방 봉기를 직접 겪은 공손찬 소속원에게 다음 해 유우의 회유를 연결하는 것은 관련성이 있다. 동탁 소속원에게 익주 부임·서원군·흑산 귀순을 연달아 출력하는 것은 관련성이 없다.

소식이 취소되는 경우도 같은 원칙이다. 무관한 사건의 `changed-news`까지 일일이 출력하지 않는다. 자신의 다음 임무 전제가 사라졌을 때만 어떤 인물/세력이 없어졌으며 현재 내 활동에 어떤 영향을 주었는지 명시한다.

### 연례 서비스와 연도 변경

- `route`의 현재 소속이 유효한 분기는 기본적으로 자동 종료한다. 재야는 기존 지원/거절/실제 다음 지역 선택을 유지한다. 5.1 동행 군주 한 명 지원 조건은 유지한다.
- 다음 소속 활동지는 기존 `lord.next`의 게임 배치로 자동 반영할 수 있으나 **그 사실만을 반복 기록하지 않는다**. 실제 다음 사건에 도착했을 때 `duty-march`를 사건별 진입문으로 써서 이전 활동과 새로운 현장을 연결한다. 관련 사건이 없는 해에 임의 명부 업무를 생성하지 않는다.
- `event-engine.ts`의 연도 증가에서 나이와 연도는 정확히 증가시키되 일반 `이어지는 발걸음` 로그를 만들지 않는다. 조용히 다음 연도의 관련 사건을 탐색하고, 공개할 기록이나 선택을 찾을 때만 반환한다. 자동 반환인데 로그도 상태 커서도 변하지 않는 무한 루프를 금한다.
- 이탈은 연례 설문 대신 실제 갈등의 선택으로 둔다. 유비의 관직 이탈, 장기 서방 주둔처럼 장소·상황이 바뀌는 사건의 후속 장면에서 `일행과 계속 간다`/`재야로 남는다`가 의미 있을 때 제공한다. 떠나면 faction=null·civilian과 위치를 보존하고 다음 재야 이동에서 목적지를 고른다. 이미 맡은 임무의 성패를 이탈로 바꾸지 않는다.

기존 `stay-or-leave`, `duty-*`, 결과 노드를 지워 진행 중 커서를 깨뜨리지 않는다. 기본 진입에서는 새 `legacy-service` 조건을 통해 우회한다. `world.flags.legacyAnnualServicePending`은 **구 저장의 커서가 해당 노드에 있을 때만** 마이그레이션에서 설정하고, 해당 기존 선택·결과를 한 번 마치면 해제한다. 그래프에는 양쪽 경로가 있어 관리자 검증의 도달 가능성을 유지한다. 신규 게임에서는 옛 선택이나 가짜 업무가 열리지 않는다. 더 간단하게 이와 동등한 명시적 커서 변환을 선택해도 되지만 과거 선택/효과 재실행은 금한다.

## 소속·지역별 연결표

이 표는 전체 사건에 인과를 조작하라는 뜻이 아니다. 같은 지역의 관련 활동과 그 지역을 떠나는 이유를 잇고, 역사적으로 관계없는 지방 사건은 건너뛴다.

| 여정 | 읽을 핵심 전개 | 연결과 종결 |
|---|---|---|
| 동탁·서방 | 서방 봉기/실제 접촉 → 미양의 대치·반란군 후퇴·추격군 보급 문제 → 한수 투항 소식 | 미양의 전과로 서방 반란 전체가 끝난 것은 아니라는 점에서 한수 소식 확인으로 연결. 투항과 해산을 구별하는 기존 후속 선택을 실질적 지역 안전 문제와 연결. 188년에 무관한 5개 기사를 재생하지 않고 서방에 남은 실제 소속·주둔 상태로 범위 종결 |
| 조조 | 왕분의 가담 권유·거절 답신 → 다음에 실제 관련 사건이 있는 낙양의 서원군 편성 | 빈 해에는 명부 일을 만들지 않음. 후방 연락에서 황제 직속군의 지휘 계통으로 업무가 달라졌음을 진입문에 설명. 조조의 직책과 건석 총지휘를 구별하고 현 소속/배치로 종결 |
| 유비 | 5.1 북방 동행 → 안희 부임·독우 갈등·관직 이탈 | 매년 동료 명부를 세지 않음. 부임 때 하던 일이 관직 이탈의 준비로 바뀌는 실제 갈등을 이어 감. 관구의 모병·하비의 공·하밀승 이후 이탈은 확보된 사실 범위에서 주어 있는 짧은 문장으로 후속 소식에 포함 가능 |
| 공손찬·유주 | 종군 선발과 장순의 불만 → 장거·장순 봉기 → 유우의 회유와 연합 약화 | 선발 갈등과 봉기를 단정적인 단일 원인으로 만들지 않음. 187년 피란/초소의 주민이 188년에도 길 안전을 묻는 맥락으로 연결. 주력 승리를 공손찬 단독 공적으로 돌리지 않음 |
| 손견 | 실제 서방 활동/접촉 → 장사 우성 진압 → 영릉·계양의 호응 세력 대응 | 서방에서 남쪽 토벌 현장으로 옮긴 이유는 확인된 활동 전환 수준으로만 설명. 새로운 전국 전투를 만들지 않음. 장사 방면 현 상태로 종결 |
| 재야 서방 | 봉기 피란 길목 → 장수의 국승 처단 주변 주민 → 다음 지역 선택 | 조려는 서방 사건이며 기주 왕분과 혼동 금지. 가까운 현장 소식으로 들어오게 하고 서로 직접 원인이라고 쓰지 않음 |
| 재야 회계/서주/북방 | 하제 현성 방어, 도겸 토벌, 장거·장순 봉기 | 고른 지역의 사건만 체험. 외지 소식은 다음 목적지를 결정할 정도의 맥락으로 묶고 사건별 독립 헤드라인은 출력하지 않음 |
| 재야 익주 | 극검의 실정·마상/조지 봉기 → 가룡 진압 → 유언 부임·면죽 기반 | 같은 피란 주민/현지 행정의 연속된 문제로 연결. 가룡이 안전을 확보한 다음 유언의 부임 행렬을 맞는 순서 유지. 부임보다 가룡 임명이 먼저였다고 쓰지 않음 |
| 재야 기주/낙양 | 장연 귀순 조건 또는 서원군 편성 | 고른 지역의 실제 일만 경험하고 무장 해산/전국 평정/정규 장교 임명을 추정하지 않음 |

## 범위 끝의 구체적 상태

공통 목록에 `chapter-5-5-closing`을 등록하는 편이 엔진의 하드코딩보다 관리·편집에 적합하다. 188년 사건들 뒤에서 조건 노드로 현재 faction/region/실제 처리 표식을 확인한다. 내용은 다음 세 요소로 쓴다.

1. 마지막 실제 활동의 결과: 수행/실패/이탈 여부는 기존 기록·표식에 근거한다.
2. 현재 실제 소속·역할·위치: 군적과 거점을 유지하거나 재야 상태임을 분명히 한다.
3. 다음 갈등의 현재 조건: 서방 반란의 잔존, 북방 귀환길의 불안, 새 익주 행정 등 **이미 수집한 미해결 상황**만 언급한다.

동탁 예: `한수의 투항 소식은 전해졌지만 서방의 병력이 모두 해산한 것은 아니었다. 나는 동탁군의 병사로 서방 거점에 남았고, 지나온 길의 안전을 계속 확인해야 했다.` 단, 한수 사건을 실제로 읽지 않았거나 전제가 취소됐으면 첫 문장을 사용하지 않는다. 이 상태를 기록하고 연대기를 볼 수 있게 마무리한다. 빈 188년을 채우기 위한 새 가상 전투나 또 다른 명부·심부름 선택은 추가하지 않는다. 필요하다면 **범위 종결의 단 한 번** 소속 유지/이탈 선택을 실제 후속 맥락에 두되 경험치 획득용 가짜 판정으로 만들지 않는다.

## 문구·표시·이전 저장

- `campaign-narrative.json`에 플레이어용 `historicalBackground`/`historicalOutcome`을 두거나 동등한 별도 문구 구조를 사용한다. 원자료 `source.background`/`reportedOutcome`의 짧은 문장을 그대로 화면에 복제하지 않는다. 5.1 결과도 명사형 요약을 사실을 보존한 유려한 문장으로 고친다. 예: `대흥산에서는 유언이 보낸 유비의 의용병이 승리했다. 관우와 장비에게 정원지와 등무가 전사하자 황건군은 와해됐고 많은 병사가 항복했다. 이 싸움은 유비 삼형제의 첫 출전이자 첫 승리였다.`
- 사실 문장 안에 사건의 주체·대상·장소를 넣으므로 기록 제목을 숨겨도 뜻이 통해야 한다. 출처·전투 ID·타입은 저장·관리자에 남는다. `HistoryFlow.tsx`에서 사실 recordType만 제목을 표시하지 않고 개인 recordType은 제목을 유지한다. 사실과 개인 창작을 합쳐 한 문단으로 만들지 않는다.
- 현재 기본 catalog를 **수정 전에** `legacy-campaign-v2.json`에 저장한다. 기존 v1→현재 보완 뒤 v2→새 기본 보완 순서로 적용한다. 문구·효과·조건·연결·배치·이미지 필드별 기존 편집을 보존한다. 명시 삭제를 복구하지 않는다.
- 이미 저장된 기록은 상태·선택·턴·능력·판정을 소급 수정하지 않는다. 이전 기본과 정확히 같은 연례 전환/소속 유지/가짜 duty 문장만 표시 selector에서 제외할 수 있다. 개인화한 관리자 문장·다른 판정 결과를 지우지 않는다. 정확한 이전 기본 사실 문장은 완결형 새 사실 문장으로 표시 보완 가능하다. 사건 ID+recordId/기존 detail을 함께 확인하고 광범위 정규식으로 임의 로그를 지우지 않는다.
- legacy `kind=history`만으로 사실 제목을 전부 숨기지 않는다. 예전 자동 로그에는 개인 행동도 포함된다. 알려진 기본 결과/노드일 때만 타입을 보완한다. Chronicle의 커스텀 생존 결과 보존 규칙을 유지한다.

## 검증 시나리오

- 동탁에 실제 접촉 후 지원 → 미양 → 한수 → 범위 끝을 **출력된 문장 전체로** 읽는다. 188년 익주·흑산·서원군·북방 기사 벽, 연례 질문·연례 명부, 반복 새해 문장이 없어야 한다. 마지막 기록은 동탁 소속과 서방의 미해결 상태를 설명한다.
- 조조·유비·공손찬·손견의 관련 사건 순서와 실제 이동 이유, 빈 해 자동 진행, 재야 지역별 여정과 익주 가룡→유언 연결을 확인한다. 본문에 실제 주어가 없는 단문이나 데이터 요약체가 남지 않아야 한다.
- 관련 없는 사건도 의존 순서상 완료되지만 로그나 커서를 무한 재생하지 않음. 정해진 사실 효과가 있는 편집 사건은 표시와 무관하게 한 번 적용됨. 사망·패망·포로 조건과 대체 승리·생포에서 모순된 소식이 없어야 한다.
- 구 저장의 stay-or-leave/duty/거절 후 travel/실제 전투 중간 커서, 이전 v1/v2 공유·부분 편집·삭제 목록을 각각 복원한다. 관리자 변경 문구를 숨기거나 기본 그래프로 갈아끼우지 않아야 한다.
- 사실 기록은 장면 제목 없이도 전체 사건이 이해되며 개인 기록의 제목은 유지된다. 신규·이전 저장 모두 같은 기록이 중복되지 않고 시점 순서와 Chronicle이 보존된다.
- 테스트는 `모든 사건이 로그에 있다`나 `매년 roster를 골랐다`라는 낡은 가정을 바꾸되 실제 전체 여정의 사실·소속·위치·완료를 검증한다. 타입·전체 테스트·빌드·검증기·재생성 안정성 및 격리된 PC/모바일/관리자 브라우저 검증을 수행한다.

### 구현 시 빠뜨리기 쉬운 두 경계

조용한 연도 진행 뒤 첫 선택/마지막 상태 화면이 나올 때 `game.year`는 이전 저장 연도이고 `event.state`/`view.year`만 다음 해일 수 있다. 날짜·나이·위치 표시에는 공개된 `view`를 사용하고, 선택 저장 시 그 상태가 실제로 커밋되도록 한다. 빈 로그 한 건이나 빈 자동 재생 카드를 넣어 이 문제를 우회하지 않는다. 자동 배경 기록이 있는 경로와 바로 선택으로 가는 경로 모두 확인한다.

현재 굵게 표시되는 `사정`, `봉기`, `조정`, `전해` 등은 서사 강조가 아니라 평범한 단어를 동명이인 장수로 잘못 연결한 결과일 수 있다. `lib/record-presentation.ts`의 `personSegments`에서 문장에 실제 인물로 나온 경우에만 연결한다. 문맥 없는 전체 장수명 스캔을 평범한 역사 산문에 적용하지 않도록 출현 인물/관련 사건 범위를 우선하고, 알려진 모호한 단어는 명시적인 인물 문맥이 없으면 평문으로 둔다. 실제 조조·동탁·유비 등의 인물 링크는 유지한다. 테스트에는 `봉기가 일어났다`, `조정이 군대를 보냈다`, `사정을 설명했다`, `소식이 전해졌다`와 실제 인물을 나란히 둔다.

5.1 sourceRecords의 secondarySummary와 후속 16개 사건의 background/reportedOutcome은 모두 플레이어용 완결형 문장으로 표현한다. `연표에는 … 적혀 있다` 같은 조사 과정은 관리자 근거로 남기고, 한수 건은 `한수가 조정에 투항했다는 소식이 전해졌다`처럼 **전달된 소식의 범위**로 기술한다. 유우의 회유 결과에는 유우/오환/반란군 연합의 주체를 직접 넣는다. 근거의 불확실성을 없애 실제 확인된 무장 해산·역사 승리로 바꾸지 않는다.

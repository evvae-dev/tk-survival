# 삼국지연의 회차별 시나리오 편집

## 작업 위치와 범위
- 자료 디렉터리 `docs/romance-three-kingdoms`의 `chapters/`에 회차마다 `001.md`~`120.md`를 독립 저장한다. 저장소 루트에서 자료 디렉터리로 이동한 뒤 아래 스크립트를 실행한다. 다른 환경에서도 이 상대 경로를 사용한다.
- 사용자가 지정한 회차만 작성한다. 최초 범위는 1~5회다. 120회까지 처리할 수 있도록 구성하되, 전체를 한 번에 작성하지 않는다.
- 최신 사용자 지시: 제11회부터 제120회까지는 추가 확인 없이 5회 작성 → 검사 → 저장 → 다음 5회 순서로 연속 진행한다. 한 번의 작업 요청에서 모든 묶음을 이어서 저장하는 것이 승인되었다. 이 지시는 아래의 일반적인 `다음` 처리보다 우선한다.
- 기존 게임의 사건 파일·DB·관리자 목록·실행 플로우에는 등록하거나 연결하지 않는다. 기존 데이터 삭제도 별도 명시적 요청이 있어야 한다.
- 원작 《삼국지연의》 통행 120회본만 서사 기준으로 쓴다. 정사, 드라마, 게임, 현대 각색의 사건을 섞지 않는다.

## 실행 절차
1. `progress.json`과 기존 회차 파일을 읽어 마지막 완료 회차 및 요청 범위를 확인한다. 기존 파일을 임의로 덮어쓰지 않는다.
2. 회목과 원문을 확인할 수 있는 공개 자료 또는 사용자 제공 원문을 대조한다. 공개 고전 원문을 우선하며 현대 번역의 표현을 복사하지 않는다. 회차 경계를 반드시 확인한다.
   - 현재 `sources/source.json`에 공개 모평본 저장소·커밋·120회 대응표가 있고 `sources/plain/001.txt`~`120.txt`에 주석을 제거한 본문이 있다. 이 자료를 먼저 사용한다.
   - `python scripts/batch.py inspect 시작회 끝회`는 문단 앞뒤 발췌만 보여 준다. 주요 흐름을 대조하는 보조 수단이며, 생략된 인물명·행동·세부 인과는 원문 전체 문단을 추가로 읽는다.
   - 문단 발췌로 대조한 파일은 `source_outline_checked`로 기록한다. 이 상태는 문장별 정밀 검증이나 모든 주요 사건의 완전한 수록을 보장하지 않는다. 원문을 실제 대조한 범위를 넘어 `verified`로 높이지 않는다.
3. 원문에 접근할 수 없으면 지식 기반 초안으로 작성할 수 있으나, 출처를 열람한 것처럼 표시하지 않는다. `progress.json`의 해당 회차를 `draft_unverified`로 표시한다. 실제 대조 후에만 `verified`로 바꾼다.
4. 아래 형식으로 회차당 독립 파일을 작성한다. 큰 사건만 추리는 대신 해당 회차의 주요 사건과 전환을 순서대로 연결한다. 보통 6~12개 전개 단계로 쓰되 분량을 채우기 위해 사건을 만들지 않는다.
5. 파일 수, 회차 중복·누락, 단계 번호, 형식, 인물의 행동 주체, 사건의 인과와 다음 회차 경계를 확인한다.
6. `progress.json`에 실제 저장한 회차, 검증 상태, 대조 자료와 다음 회차를 기록한다. 생성 예정인 파일을 완료 처리하지 않는다.
   - 5회 묶음은 `scripts/batch.py`의 `save`로 저장할 수 있다. 입력은 제목, 설명, `단계명|상세 내용` 줄로 구성한 회차 다섯 개이며 회차 사이를 `===` 줄로 나눈다. 본문 형식과 최소 분량을 검사하고 기존 회차 덮어쓰기를 거부한다.
   - `python scripts/validate.py`로 120개 회차의 번호·형식·누락 및 원문 매핑을 확인한다. 이 검사는 서사의 정확성을 자동 보증하지 않는다.
7. 사용자가 `다음`이라고 하면 미작성 구간 중 다음 스토리 아크를 이어 쓴다. 회차를 중간에서 쪼개지 않으며, 분량이 지나치게 길면 최대 5회씩 저장하고 진행 상태에 남긴다. 명시적 회차 지정이 항상 우선한다.

## 파일 본문 형식
첫 줄은 `제N회: 사건명 (핵심 사건)` 형태의 제목이며 Markdown 제목 기호 없이 쓴다. 다음 줄에 2~4문장 설명을 쓴다. 이후 정확히 `🎬 주요 전개 과정`을 쓰고 번호 단계와 `•` 불릿으로 상세 내용을 정리한다.

```text
제1회: 도원결의와 황건적의 난 (유비·관우·장비의 거병)
사건의 배경과 핵심 갈등 및 의미를 설명합니다.
🎬 주요 전개 과정
1. 단계 제목
• 누가 어떤 상황에서 무엇을 원했고 어떤 행동을 했는지 설명합니다.
• 상대 반응과 결과가 다음 행동을 어떻게 유발했는지 설명합니다.
2. 다음 단계 제목
• 이어지는 사건을 설명합니다.
```

## 서사 기준
- 한국어 경어체로 작성한다. 제목·설명·전개 외에 개요, 분석, 인사말, 맺음말을 본문에 추가하지 않는다.
- 각 단계에 배경 → 행동 주체와 목표 → 구체적인 행동 → 상대 반응·결과를 가능한 범위에서 드러낸다.
- 협력·배신·철수·진격 등 원작 인물의 실제 선택과 제약을 상세히 드러내어 추후 게임 분기를 설계할 근거를 남긴다.
- 가상 선택지, 능력치, 효과, 사건 ID, 플레이어 개입, 가상의 대사·결말을 원작 요약에 추가하지 않는다. 게임 설계는 별도 요청으로 처리한다.
- 연의의 허구·신이한 묘사는 삭제하거나 역사적 사실로 단정하지 말고 작품 속 전개로 서술한다.
- 후속 회차의 결과를 미리 확정하지 않는다. 특히 제1회는 장비가 동탁을 베려는 대목, 제2회는 십상시의 하진 유인, 제3회는 폐립 추진, 제4회는 조조의 거병, 제5회는 호뢰관 패전 이후까지의 경계를 점검한다.
- 원문 출처·판본 이견·미확인 사항은 회차 본문이 아니라 `progress.json`에 기록한다. 자료를 실제 확인한 경우에만 URL·확인 범위를 기록한다.

## 원작 자료 담당 인계 지시 — 2026-10-23

[사건 참여 계약](../../../docs/EVENT_PARTICIPATION_CONTRACT.md)의 게임 분기는 별도 설계 영역이다. 원작 요약 담당은 사건 성립의 근거가 되는 인물·장소·만남·약속·동행·결말의 인과를 원문 범위에서 명확히 남겨라. 원문에 없는 주인공의 초대·유비 접촉 실패·황건 합류·대체 생존을 회차 원본에 추가하지 말라.

게임 기획 담당에게 해당 회차·전개 단계와 확인된 사실/미확인 부분을 인계하라. 게임의 불참·취소 경로를 원작 사건 삭제로 처리하지 않는다. 이번 스킬 정비는 원작 120회 파일을 다시 작성하라는 요청이 아니다.

## 최종 전달
- 파일 저장을 요청받았다면 요약 본문을 채팅에 다시 출력하지 않는다. 생성된 파일 링크만 간결하게 전달한다.
- 다른 세션에서도 이 스킬을 쓰려면 저장소의 `.agents/skills/romance-chapter-editor/SKILL.md`를 읽거나 해당 환경의 스킬 경로에 이 스킬 폴더를 설치해야 한다. 자동으로 전역 등록되었다고 주장하지 않는다.
